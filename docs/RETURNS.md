# المرتجعات ورصيد المتجر — Returns & Store Credit

وحدة `returns` داخل ARUMA CORE (`apps/core/src/modules/returns`). رصيد المتجر في وحدة `finance` (`store-credit.ts`).

## المسار الكامل

```
مسودة ─إرسال─► بانتظار رد التاجر ─قبول─► مقبول ─استلام/إيداع─► في الطريق ─► استُلم ─فحص ناجح─► مكتمل
                    │                         │ (الزبون يحتفظ بالمنتج: يُحل فورًا)            │      (أو «الاسترداد قيد الإرسال»)
                    ├─رفض─► مرفوض ─الزبون يطلب المراجعة─┐                                  └─فحص فاشل─► الفحص فاشل
                    └─لا رد خلال 48 ساعة────────────────► مراجعة ARUMA ◄─الزبون يطلب المراجعة─────┘
                                                            └─قرار ARUMA نهائي: قبول (أو حل مباشر) / رفض
```

| المرحلة | من | التفاصيل |
|---|---|---|
| **طلب الإرجاع** (Return Request) | الزبون | منتجات من طلب مُسلَّم، كلها أو جزء منها، خلال **7 أيام** من التسليم (قابلة للتغيير). لا يمكن إرجاع نفس المنتج مرتين. |
| **السبب** (Reason) | الزبون | وصل تالفًا، معيب، منتج خاطئ، ليس كما وُصف، أجزاء ناقصة، يُشتبه أنه مقلّد، غيّر رأيه، سبب آخر. مع وصف إلزامي. |
| **الإثبات** (Evidence) | الزبون والتاجر وARUMA | صور JPEG/PNG/WebP أو PDF، حتى 10 ملفات، 10 ميغابايت لكل ملف. **إلزامي** إذا كان الخطأ من التاجر (كل الأسباب ما عدا «غيّر رأيه» و«سبب آخر»). يُفحص النوع الحقيقي للملف، ويُخزّن مشفّرًا، ولا يُحذف. |
| **رد التاجر** (Merchant Response) | المالك أو المدير | قبول مع طريقة العودة (استلام من الزبون، أو إيداع، أو يحتفظ به الزبون)، أو رفض بسبب إلزامي. المهلة 48 ساعة، وبعدها يُحال الطلب تلقائيًا إلى ARUMA. |
| **مراجعة ARUMA** (Admin Review) | مدير ARUMA | عند طلب الزبون (خلال 7 أيام من الرفض أو فشل الفحص)، أو عند انتهاء مهلة التاجر. **قرار ARUMA نهائي.** |
| **القبول** (Approval) | التاجر أو ARUMA | الحل يكون ما طلبه الزبون، أو الاسترداد. لا يُفرض على الزبون رصيد بدل المال الذي طلبه. |
| **الرفض** (Rejection) | التاجر أو ARUMA | بسبب يراه الزبون. رفض ARUMA نهائي. |
| **الاستلام** (Pickup) | التاجر | طرد عكسي من الزبون إلى التاجر (عنوان الإرجاع للتاجر)، مع شركة توصيل ورقم تتبع أو بسائق التاجر. أو يُحضره الزبون. |
| **الفحص** (Inspection) | المالك أو المدير | لكل منتج: يعود للبيع أم لا (مثل عطر مفتوح). **ناجح**: يُحل الطلب. **فاشل**: بسبب إلزامي، ويمكن للزبون طلب مراجعة ARUMA. |

## الحلول

| الحل | ما يحدث |
|---|---|
| **استرداد المال** (Refund) | عبر خدمة الدفع. **الدفع الإلكتروني:** تلقائي عبر المزوّد. **الدفع عند الاستلام:** المال يُعاد بتحويل (CCP/بنك) تقوم به ARUMA، وتسجّله بمرجع التحويل، والإرجاع يبقى «الاسترداد قيد الإرسال» حتى ذلك. |
| **استرداد جزئي** (Partial Refund) | عند الفحص (أو قرار ARUMA): مبلغ أقل من المقبول، **مع سبب إلزامي**. لا يمكن تجاوز المبلغ المقبول. |
| **استبدال** (Replacement) | طلب جديد مجاني (المجموع 0) لنفس العنوان وبنفس طريقة التوصيل، مرتبط بالطلب الأصلي، يُحجز له المخزون ويُشحن عاديًا. إذا نفد المخزون يُرفض الاستبدال، وARUMA تقرر حلًا آخر (استرداد). |
| **رصيد المتجر** (Store Credit) | يُضاف فورًا لرصيد الزبون، ويُستعمل في أي طلب لاحق. |

**المبلغ المستحق:**
- قيمة المنتجات المُرجعة.
- **سعر التوصيل يُعاد أيضًا** إذا عاد الطلب كله بسبب خطأ التاجر.
- عند «تغيير الرأي» تُخصم رسوم الإرجاع التي يحددها المتجر (حاليًا 0).
- في كل الحالات: ما دُفع **برصيد المتجر يعود رصيدًا**، والباقي مالًا. لا يُسترد مال أكثر مما دُفع مالًا.

**أثره على الطلب:**
- إذا عادت كل منتجات الطلب يصبح الطلب «مُرجعًا».
- إذا عادت كل قيمته (مالًا أو رصيدًا) يصبح «مستردًا».
- إرجاع جزء من الطلب يتركه «مُسلَّمًا».

**أثره المالي (الدفتر):**
- الاسترداد والرصيد يُخصمان من التاجر وARUMA بالتناسب: التاجر يعيد حصته، وARUMA تعيد حصتها من العمولة. هذه نفس قاعدة الاسترداد ([FINANCE.md](FINANCE.md)).
- إن كان المال في فترة الحجز يُخصم من «قيد الانتظار»، وإلا من «المتاح» (وقد يصبح سالبًا فيُخصم من التحويلات القادمة).

## رصيد المتجر (Store Credit)

| الحركة | متى | الدفتر المالي |
|---|---|---|
| **منح** (issued) | إرجاع يُحل برصيد، أو جزء الاسترداد الذي دُفع برصيد | التاجر وARUMA يعيدان حصتيهما ← التزام «رصيد المتجر» |
| **استعمال** (used) | `useStoreCredit: true` عند الطلب: الرصيد يدفع أولًا، والباقي إلكترونيًا أو نقدًا | التزام «رصيد المتجر» ← «أموال الطلبات المحجوزة» |
| **إعادة** (restored) | إلغاء طلب دُفع برصيد قبل التسليم | «أموال الطلبات المحجوزة» ← التزام «رصيد المتجر» |

- **الدفع عند الاستلام مع رصيد:** السائق يحصّل الباقي فقط، والتاجر يستحق جزء الرصيد عند التسليم.
- إذا غطّى الرصيد الطلب كله، فلا دفع ولا تأكيد نقدي.
- **الحماية:**
  - الحركات append-only.
  - الرصيد لا يمكن أن يكون سالبًا، ولا يمكن تغييره إلا ليساوي آخر حركة (قاعدة البيانات تتحقق).
  - الحساب مقفل أثناء الطلب، فلا يُصرف مرتين.
  - المطابقة المالية تتحقق أن **مجموع أرصدة الزبائن = التزام رصيد المتجر في الدفتر**.
- الرصيد لكل عملة، وليس له تاريخ انتهاء حاليًا.

## القواعد القابلة للتغيير (Return Policy)

قاعدة للمنصة وقاعدة لكل متجر، يغيّرها مدير ARUMA.

| الإعداد | الافتراضي |
|---|---|
| مهلة طلب الإرجاع بعد التسليم | 7 أيام (= فترة حجز رصيد التاجر) |
| مهلة رد التاجر | 48 ساعة |
| مهلة طلب مراجعة ARUMA | 7 أيام |
| قبول الإرجاع لتغيير الرأي | نعم (المنتج يجب أن يعود غير مفتوح، ويقرر ذلك الفحص) |
| رسوم إرجاع تغيير الرأي | 0 دج |

## الحماية

- سجل الإرجاع (`return_events`) والإثباتات: append-only. الإرجاع لا يُحذف.
- كل خطوة تُسجّل: من، ومتى، ومن أي حالة إلى أي حالة، ولماذا.
- الزبون لا يرى أسماء موظفي التاجر ولا مرجع التحويل الداخلي.
- التاجر لا يرى الإرجاع وهو مسودة، ولا إرجاعات تاجر آخر.
- التاجر لا يرسل المال أبدًا: الاسترداد عبر نظام الدفع في ARUMA فقط.

## الواجهات (API)

**الزبون:**

| الطريقة | المسار |
|---|---|
| POST | `/v1/me/orders/:orderId/returns` `{lines, reason, description, resolution}` |
| GET | `/v1/me/returns`، و`/v1/me/returns/:id` |
| POST / GET | `/v1/me/returns/:id/evidence` (multipart)، و`/evidence/:evidenceId` |
| POST | `/v1/me/returns/:id/submit`، و`/cancel`، و`/escalate` `{reason}` |
| GET | `/v1/me/store-credit` |
| POST | `/v1/stores/:slug/orders` مع `useStoreCredit: true` |

**التاجر** (`/v1/merchants/:id/returns/:returnId`):

| الطريقة | المسار | من |
|---|---|---|
| GET | `/v1/merchants/:id/returns` و`/:returnId` | كل الأعضاء |
| POST | `/respond` `{decision, resolution, returnMethod, note}` | مالك، مدير |
| POST | `/pickup` و`/pickup/status` و`/receive` | كل الأعضاء |
| POST | `/inspection` `{result, lines[{returnLineId, restock}], amountMinor?, partialReason?, note}` | مالك، مدير |
| POST / GET | `/evidence` | كل الأعضاء |

**ARUMA:**

| الطريقة | المسار |
|---|---|
| GET | `/v1/admin/returns`، و`/v1/admin/returns/:id` (الدعم والمدير) |
| POST | `/v1/admin/returns/:id/decision` `{decision, resolution?, returnMethod?, amountMinor?, partialReason?, note}` (المدير، نهائي) |
| POST | `/v1/admin/returns/:id/refund` `{externalReference?}` (إرسال أو تسجيل الاسترداد) |
| GET / PUT / DELETE | `/v1/admin/returns-policy?storeId=` |
| GET | `/v1/admin/finance/store-credit/:userId` |

**مهمة تلقائية** كل 5 دقائق: الطلبات التي لم يرد عليها التاجر في المهلة تُحال إلى ARUMA.

## قبل الإطلاق

1. **سياسة الإرجاع المكتوبة للزبائن:** المدة، والشروط (العطور المفتوحة)، ومن يدفع التوصيل، والرصيد. يجب أن تطابق الإعدادات وتُراجع قانونيًا، وفق قانون حماية المستهلك الجزائري 09-03 والقانون 18-05 للتجارة الإلكترونية.
2. **إجراء داخلي في ARUMA:** من يراجع النزاعات، ومن ينفذ تحويلات الاسترداد لطلبات الدفع عند الاستلام ويسجّل مراجعها، ومهلة التنفيذ.
3. **واجهة الإدارة:** قرارات ARUMA متاحة حاليًا عبر الـAPI فقط. صفحة إدارية للمراجعات تأتي مع لوحة إدارة ARUMA.
4. **إشعارات الزبون:** إرسال SMS أو بريد عند كل خطوة، يُبنى على الحدث `returns.return.status_changed` المسجّل، ويحتاج مزوّد SMS.
