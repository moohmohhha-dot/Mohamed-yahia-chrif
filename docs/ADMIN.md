# لوحة إدارة ARUMA — Admin Panel

تطبيق مستقل لفريق ARUMA: `apps/admin` (React، عربي/فرنسي/إنجليزي، يدعم الكتابة من اليمين لليسار).
الـAPI في ARUMA CORE: وحدة `admin` + المسارات الإدارية لكل وحدة (`/v1/admin/...`).

## الأدوار الستة

| الدور | المسؤوليات |
|---|---|
| **Super Admin** (مدير عام) | كل شيء، ومنح الأدوار وسحبها، ومفاتيح الميزات. يُحصر في عدد قليل جدًا من الأشخاص. |
| **Finance Admin** (مسؤول المالية) | الدفتر المالي، العمولة، التسويات، التحويلات، **تنفيذ الاسترداد**، المطابقة مع خدمة الدفع. |
| **Support Admin** (مسؤول الدعم) | المستخدمون والطلبات، **الحكم** في المرتجعات والنزاعات، الملاحظات الداخلية. لا يدفع المال: الاسترداد من صلاحية المالية. |
| **Content Admin** (مسؤول المحتوى) | المنتجات (الحظر وفكّه)، مراجعة التقييمات، البحث (المرادفات، إعادة الفهرسة)، المحتوى والإعلانات (عند جاهزيتها). |
| **Security/Fraud Admin** (مسؤول الأمان والاحتيال) | سجل التدقيق، إيقاف المستخدمين، إنهاء الجلسات، مخاطر الدفع عند الاستلام وحظر الأرقام. |
| **Operations Admin** (مسؤول العمليات) | توثيق التجار، إيقافهم، الطلبات، التوصيل وشركاته، قواعد الدفع عند الاستلام، سياسة الإرجاع، القسائم والمكافآت (عند جاهزيتها). |

- يمكن للشخص أن يحمل **عدة أدوار**.
- ما يستطيعه كل دور مكتوب في الكود (`apps/core/src/modules/identity/permissions.ts`)، ويظهر كجدول في «الفريق والأدوار».
- تغيير هذا الجدول تغيير في الكود: يُراجَع ويُختبر، وليس إعدادًا يُغيَّر بصمت.
- **الخادم يتحقق من الصلاحية في كل طلب.** اللوحة تُخفي فقط ما لا يحق للدور رؤيته.

## الحماية

- **منح دور أو سحبه** يحتاج سببًا مكتوبًا، ويحفظ من فعل ومتى. السجل لا يُحذف ولا يُعاد كتابته (محمي في قاعدة البيانات).
- **المدير العام:**
  - لا يسحب دوره بنفسه.
  - لا يمكن حذف آخر مدير عام.
- **حسابات الفريق** لا يوقفها إلا مدير عام، ولا أحد يتصرف في حسابه الشخصي.
- **تضارب المصالح:** عضو الفريق لا يقرر شيئًا يخص تاجرًا هو عضو فيه. يشمل ذلك:
  - التوثيق والإيقاف والعمولة؛
  - التسوية والتحويل؛
  - حظر المنتج؛
  - المرتجعات والنزاعات والتقييمات.
  
  في هذه الحالات يجب أن يقرر عضو آخر.
- **البيانات الحساسة:** الأرقام الكاملة للهوية والحساب البنكي تظهر فقط لمن يملك صلاحية التوثيق، وكل فتح للملف أو الوثيقة يُسجَّل. البقية يرون آخر 4 أرقام.
- **إيقاف المستخدم:** يُخرجه فورًا من كل أجهزته.
- **فصل المهام:** الدعم يحكم والمالية تدفع. قرار الاستئناف في النزاع يصدره مدير آخر غير صاحب القرار الأول.
- **سجل التدقيق:** كل إجراء له سبب ويُسجَّل باسم صاحبه. لا يُعدَّل ولا يُحذف حتى من المدير العام.
- **جلسة اللوحة** منفصلة عن جلسة Merchant Center.

| الثقة والأمان | Reviews | قائمة المراجعة والبلاغات: نشر، رفض، إخفاء، إعادة |
| | Fraud | مخاطر الزبون، حظر الأرقام ورفعه، قواعد الدفع عند الاستلام |
| | Security | سجل التدقيق مع البحث |
| النمو | Ads, Coupons, Rewards | **قريبًا** (المرحلة 3 و2): الأدوار والصلاحيات جاهزة، ولا بيانات وهمية |
| المنصة | Support, CMS | **قريبًا** (المرحلتان 2 و1) |
| | AI | المزوّد، المفتاح الرئيسي ومفتاح كل ميزة (بسبب مكتوب)، الاستهلاك والأعطال لكل ميزة ([AI.md](AI.md)) |

## الواجهات الجديدة (API)

| الطريقة | المسار | الصلاحية |
|---|---|---|
| GET | `/v1/admin/me` (الأدوار والصلاحيات) | أي عضو في الفريق |
| GET | `/v1/admin/overview` | `overview.read` |
| GET | `/v1/admin/analytics?days=` | `analytics.read` |
| GET | `/v1/admin/users?q=&status=&staff=`، `/v1/admin/users/:userId` | `users.read` |
| POST | `/v1/admin/users/:userId/suspend` و`/reactivate` `{reason}` | `users.manage` |
| POST | `/v1/admin/users/:userId/sessions/end` `{reason}` | `security.manage` |
| GET | `/v1/admin/staff` | `staff.manage` أو `security.read` |
| POST | `/v1/admin/users/:userId/staff-roles` `{role, reason}` | `staff.manage` |
| POST | `/v1/admin/users/:userId/staff-roles/:role/revoke` `{reason}` | `staff.manage` |
| GET | `/v1/admin/products`، `/v1/admin/products/:id`، `/v1/admin/offers` | `catalog.read` |
| POST | `/v1/admin/products/:id/block` و`/unblock` `{reason}` | `catalog.moderate` |
| GET | `/v1/admin/inventory?low=true` | `inventory.read` |
| GET | `/v1/admin/payments` | `payments.read` |
| GET | `/v1/admin/finance/settlements` | `finance.read` |

| GET / PUT | `/v1/admin/feature-flags`، `/:key` `{enabledByDefault, reason}`، `/:key/stores/:storeId` `{enabled \| null, reason}` | `flags.read` / `flags.manage` |

المسارات الإدارية القديمة (التجار، الطلبات، المالية، المرتجعات، النزاعات، التقييمات، الدفع عند الاستلام، التوصيل) أصبحت كلها محمية بصلاحية بدل «admin/support».

## أول مدير عام

لا يمكن إنشاء أول مدير عام من اللوحة. يُنشأ من سطر أوامر الخادم:

```
DATABASE_URL=... pnpm --filter @aruma/core make-admin someone@example.com
```

بعدها يمنح المدير العام الأدوار من «الفريق والأدوار». المديرون والدعم السابقون نُقلوا تلقائيًا إلى Super Admin وSupport Admin.

## التشغيل

```
pnpm --filter @aruma/admin dev      # http://localhost:5174 (الـAPI على :3000)
pnpm --filter @aruma/admin e2e      # اختبار كامل في المتصفح
```

## قبل الإطلاق

1. ✅ **التحقق بخطوتين إلزامي لكل حسابات الفريق** (مبني: [SECURITY.md](SECURITY.md)). جلسات الفريق 12 ساعة كحد أقصى، و30 دقيقة دون نشاط.
2. **نشر اللوحة على نطاق منفصل** (مثلًا `admin.aruma…`) مع تقييد الوصول (شبكة خاصة أو VPN أو قائمة عناوين IP).
3. **التحقق من البريد الإلكتروني** لحسابات الفريق (لا يوجد بعد تحقق من بريد المستخدم في ARUMA).
4. **سياسة داخلية مكتوبة:** من يحمل أي دور، مديران عامّان على الأقل، ومراجعة دورية لسجل الأدوار وسجل التدقيق.
5. **مراجعة جدول الصلاحيات** مع المسؤولين قبل الإطلاق، خاصة: من يحكم في النزاعات، ومن يغيّر العمولة.
