# البنية التقنية — ARUMA MARKET

## الملخص لصاحب المشروع

- **ARUMA MARKET** هي المنظومة (المنصة). **MB Parfum** هو أول «متجر» (store) يعمل داخلها.
- نبني **نظامًا واحدًا منظّمًا في وحدات** (Modular Monolith)، وليس خدمات مصغّرة (Microservices).
  السبب: أسرع في البناء، أرخص في التشغيل، وأسهل في الإصلاح. وكل وحدة معزولة بحيث يمكن فصلها لاحقًا
  كخدمة مستقلة إذا ظهرت حاجة تقنية حقيقية (ضغط كبير على البحث أو الدفع مثلًا).
- قاعدة البيانات مصمّمة من اليوم الأول لتدعم: **عدة متاجر، عدة تجار، عدة دول، عدة عملات، عدة لغات**،
  دون أن نبني الآن شاشات أو منطقًا لا نحتاجه بعد.

## التقنيات المختارة

| الطبقة | التقنية | لماذا |
|---|---|---|
| اللغة | TypeScript (Node.js 22) | لغة واحدة للواجهة والخادم، أخطاء أقل بفضل الأنواع |
| الخادم (API) | Fastify 5 | سريع، خفيف، ناضج |
| التحقق من المدخلات | Zod | كل طلب يُفحص قبل أن يصل للمنطق |
| قاعدة البيانات | PostgreSQL 16 | موثوقة، تدعم المعاملات المالية وJSON والبحث |
| الوصول للبيانات | Drizzle ORM | استعلامات مكتوبة بالأنواع + ملفات migration بصيغة SQL واضحة |
| الاختبارات | Vitest | اختبارات تعمل على قاعدة بيانات حقيقية منفصلة |
| تنظيم الكود | pnpm workspaces (monorepo) | كل التطبيقات والحزم في مستودع واحد |

## هيكل المستودع

```
apps/
  api/                 ← الخادم (REST API) لكل المنصة
    src/modules/       ← كل وحدة عمل في مجلدها: stores, catalog, (لاحقًا: cart, orders, payments…)
    src/shared/        ← أدوات مشتركة (الأخطاء، المال)
    test/              ← الاختبارات
packages/
  db/                  ← مخطط قاعدة البيانات، الـmigrations، والبيانات التجريبية
docs/                  ← التوثيق
```

الواجهات القادمة (متجر MB Parfum، لوحة التحكم، لوحة التاجر) ستُضاف في `apps/` وتستعمل نفس الـAPI.

## نموذج البيانات

```
store (متجر/تطبيق: MB Parfum)          vendor (تاجر)
  ├─ store_locales    (ar, fr, en)        └─ store_vendors (أي تاجر يبيع في أي متجر + العمولة)
  ├─ store_currencies (DZD, EUR, USD)
  ├─ store_countries  (DZ)
  ├─ categories ─ category_translations
  ├─ brands
  └─ products (store_id + vendor_id)
       ├─ product_translations (الاسم والوصف لكل لغة)
       ├─ product_categories
       ├─ product_images
       └─ product_variants (الحجم، المخزون، SKU)
            └─ variant_prices (سعر صريح لكل عملة)
```

### قرارات مهمة تمنع مشاكل التوسع لاحقًا

1. **كل منتج مرتبط بمتجر وبتاجر.** اليوم MB Parfum هو التاجر الوحيد، وغدًا يدخل تجار آخرون دون تغيير الجداول.
2. **المال يُخزَّن كعدد صحيح بالوحدة الصغرى** (سنتيم) مع رمز العملة (ISO 4217). لا نستعمل الأعداد العشرية أبدًا، لتجنّب أخطاء التقريب.
3. **لا تحويل تلقائي للعملات.** لكل حجم سعر محدد لكل عملة. التحويل بسعر الصرف يمكن إضافته لاحقًا كوحدة منفصلة.
4. **النصوص في جداول ترجمة** وليست داخل جدول المنتج. إضافة لغة جديدة = صفوف جديدة فقط. العربية معرّفة كلغة `rtl`.
5. **خصائص كل مجال في حقل `attributes` (JSONB).** للعطور: النوتات، التركيز (EDP/EDT)، الجنس. متجر إلكترونيات مستقبلي يستعمل نفس الجداول بخصائص مختلفة.
6. **المعرّفات UUID** وليست أرقامًا متسلسلة، حتى لا يمكن تخمينها وحتى يسهل دمج البيانات بين الأنظمة.
7. **التواريخ مع المنطقة الزمنية** (`timestamptz`).

## واجهة الـAPI الحالية (v1)

كل المسارات تبدأ بـ `/v1/stores/:storeSlug` ليكون كل طلب مرتبطًا بمتجر معيّن.

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/health` | حالة الخادم وقاعدة البيانات |
| GET | `/v1/stores/:storeSlug` | معلومات المتجر، لغاته وعملاته |
| GET | `/v1/stores/:storeSlug/categories?locale=` | التصنيفات مترجمة |
| GET | `/v1/stores/:storeSlug/products?locale=&currency=&category=&page=&pageSize=` | قائمة المنتجات |
| GET | `/v1/stores/:storeSlug/products/:productSlug?locale=&currency=` | تفاصيل منتج مع أحجامه وأسعاره |

- إذا لم تُحدَّد اللغة أو العملة تُستعمل الافتراضية للمتجر (MB Parfum: العربية، الدينار الجزائري).
- إذا نقصت ترجمة لمنتج في لغة ما، يُعرض النص بلغة المتجر الافتراضية.
- الأخطاء بصيغة موحّدة: `{ "error": { "code": "…", "message": "…" } }`.

## متى نفصل خدمة مستقلة (Microservice)؟

فقط عند وجود سبب قابل للقياس، مثل:
- وحدة تحتاج توسعًا مختلفًا جدًا عن الباقي (مثل البحث عند ملايين المنتجات).
- متطلبات أمان أو امتثال تفرض العزل (مثل معالجة بيانات البطاقات).
- فريق مستقل يحتاج نشر وحدته بشكل منفصل.

إلى ذلك الحين، تبقى الوحدات داخل نفس الخادم وتتواصل عبر دوال واضحة، وليس عبر الشبكة.
