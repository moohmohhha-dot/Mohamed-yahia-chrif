# المالية: الدفتر المالي (Ledger)

وحدة `finance` داخل ARUMA CORE (`apps/core/src/modules/finance`). هي سجل محاسبي **قابل للتدقيق** يحفظ كل ما يتعلق بالمال: المبيعات، العمولة، الرسوم، الاسترجاعات، أرصدة التجار، التسويات، التحويلات، ورسوم مزوّد الدفع.

## القاعدة الأساسية: رصيد قاعدة البيانات ليس مالًا

الأرقام في الدفتر **سجلات لما هو مستحق**، وليست مالًا حقيقيًا. المال الحقيقي يتحرك فقط خارج ARUMA:

| الحركة | من يحرك المال فعلًا | ماذا يفعل الدفتر |
|---|---|---|
| الزبون يدفع إلكترونيًا | مزوّد الدفع (Chargily، انظر [PAYMENTS.md](PAYMENTS.md)) | يسجل أن المال وصل إلى حساب المزوّد بعد تأكيد المزوّد فقط |
| المزوّد يحوّل المال إلى حساب ARUMA البنكي | المزوّد | المدير يسجل التحويل مع رسوم المزوّد ومرجعه |
| ARUMA تدفع للتاجر | تحويل بنكي أو بريدي (CCP) حقيقي يقوم به فريق المالية | يُسجَّل «مدفوع» **فقط** مع رقم مرجع التحويل الحقيقي |
| الزبون يدفع عند الاستلام | التاجر أو شركة التوصيل تستلم النقود | يسجل أن التاجر يدين لـARUMA بالعمولة |

لا يوجد في ARUMA أي زر «أرسل المال». لا يمكن لأي رقم في الدفتر أن يصبح مالًا إلا عبر بنك أو مزوّد دفع.

## مثال المهمة

طلب بـ 10,000 دج، عمولة 8%، دفع إلكتروني:

| الحدث | القيد |
|---|---|
| الدفع | حساب المزوّد +10,000 ← أموال طلبات محجوزة +10,000 |
| التسليم | أموال محجوزة −10,000 ← **رصيد التاجر قيد الانتظار +9,200** + **عمولة ARUMA +800** |
| بعد 7 أيام (فترة الحجز) | قيد الانتظار −9,200 ← **متاح +9,200** |
| التسوية | متاح −9,200 ← مُسوّى +9,200، وإنشاء أمر تحويل |
| التحويل | مُسوّى −9,200 ← قيد التحويل، ثم يخرج من البنك عند تأكيد التحويل الحقيقي |

**الدفع عند الاستلام:** التاجر استلم 10,000 نقدًا، فيسجل الدفتر أنه يدين لـARUMA بـ 800 (رصيد سالب −800). يُخصم هذا المبلغ تلقائيًا من تحويلاته القادمة.

هذا المثال موجود حرفيًا في الاختبارات (`apps/core/test/finance.test.ts`).

## القيد المزدوج

- كل حركة **قيد** (journal entry) فيه سطور مدين ودائن. **مجموع المدين = مجموع الدائن دائمًا.**
- قاعدة البيانات نفسها ترفض أي قيد غير متوازن عند الحفظ (trigger مؤجل حتى نهاية المعاملة).
- القيود والسطور **لا تُعدّل ولا تُحذف**. الخطأ يُصحح بقيد عكسي جديد، فيبقى كل شيء ظاهرًا للمدقق.
- كل قيد له مصدر فريد (نوع + مصدر + معرّف). لذلك تكرار نفس الحدث (webhook مكرر مثلًا) لا يسجل المال مرتين.
- المبالغ أعداد صحيحة بأصغر وحدة (سنتيم)، ولا توجد أعداد عشرية.

### الحسابات

| الحساب | معناه |
|---|---|
| `provider_clearing` | مال عند مزوّد الدفع لم يصل بعد إلى بنك ARUMA |
| `bank` | حساب ARUMA البنكي |
| `order_funds_held` | مال طلبات مدفوعة لم تُسلَّم بعد |
| `merchant_pending` | رصيد التاجر خلال فترة الحجز (Pending Balance) |
| `merchant_available` | رصيد التاجر المتاح للتسوية (Available Balance) |
| `merchant_settled` | تمت تسويته، في انتظار التحويل |
| `payouts_in_transit` | تحويلات أُرسلت ولم يتأكد وصولها |
| `commission_revenue` | عمولة ARUMA |
| `fee_revenue` | رسوم ARUMA على الطلب |
| `provider_fees_expense` | رسوم مزوّد الدفع (مصروف على ARUMA) |

## العمولة: قابلة للتغيير وليست مكتوبة في الكود

- العمولة الأولية **8%** محفوظة كقاعدة في قاعدة البيانات (`commission_rules`، 800 نقطة أساس = 8%)، وليست رقمًا في الكود.
- الأولوية: **استثناء خاص بالتاجر في متجر معين** ← **قاعدة المتجر** (مثل MB Parfum) ← **قاعدة المنصة**.
- كل قاعدة لها تاريخ بدء وسبب، ولا تُحذف. تغيير العمولة يعني إضافة قاعدة جديدة بتاريخ بدء جديد، فيبقى تاريخ كل نسبة محفوظًا.
- **العمولة تُحفظ في كل طلب لحظة الشراء.** تغيير القاعدة لاحقًا لا يغيّر الطلبات القديمة.
- العمولة تُحسب على **السلع** التي دفعها الزبون فعلًا (بعد أي استرجاع قبل التسليم)، وتُعترف بها عند **التسليم**.
- **سعر التوصيل لا تُحسب عليه عمولة**: يذهب للتاجر لأنه يدفع لشركة التوصيل أو يوصل بنفسه. مثال: سلع 5,000 دج + توصيل 400 دج = عمولة 400 دج، ومستحق التاجر 5,000 دج ([SHIPPING.md](SHIPPING.md)).
- رسوم ثابتة لكل طلب (`order_fee_minor`) متاحة أيضًا. قيمتها حاليًا 0.
- التاجر لا يستطيع تغيير العمولة. يراها فقط للاطلاع.

## فترة الحجز (Pending → Available)

- بعد التسليم يبقى مستحق التاجر **قيد الانتظار** لمدة `hold_days` (حاليًا 7 أيام، قابلة للتغيير)، لتغطية الإرجاع.
- مهمة تلقائية كل 5 دقائق تنقل المستحقات التي انتهت مدتها إلى **متاح**.

## الاسترجاع (Refund)

- **قبل التسليم:** يعود المال المحجوز إلى حساب المزوّد، ولا توجد عمولة.
- **بعد التسليم:** يرد التاجر وARUMA حصتيهما بالتناسب. مثال: استرجاع 1,000 من طلب 10,000 = 920 من التاجر و80 من العمولة. الرسوم الثابتة لا تُرد.
- **الدفع عند الاستلام:** التاجر يرد للزبون مباشرة، وARUMA تعيد له حصتها من العمولة.
- الاسترجاع يبدأ فقط من المدير عبر خدمة الدفع (انظر [PAYMENTS.md](PAYMENTS.md)). التاجر لا يملك زر استرجاع.

## التسوية والتحويل (Settlement & Payout)

1. **التسوية** (المدير): تأخذ كامل الرصيد المتاح للتاجر وتنشئ تسوية برقم `ST-2026-000001` مع تفصيل (مبيعات، عمولة، رسوم، استرجاعات).
   - تُرفض إذا لم يكن حساب السحب موثقًا، أو كانت عملته مختلفة، أو لم يوجد رصيد موجب.
2. **أمر التحويل** يُنشأ تلقائيًا إلى حساب السحب الموثق. يُحفظ فيه فقط آخر 4 أرقام واسم البنك، والرقم الكامل يبقى مشفرًا في ملف التاجر.
3. **الحالات:** `requested` ← `sent` (أُرسل التحويل في البنك) ← `paid` (**رقم مرجع التحويل إلزامي**) أو `failed` (السبب إلزامي، ويعود المبلغ إلى رصيد التاجر المتاح).
   - قاعدة البيانات تمنع تغيير المبلغ أو الوجهة، وتمنع أي انتقال آخر بين الحالات.

## رسوم مزوّد الدفع

عندما يحوّل Chargily المال إلى بنك ARUMA، يسجل المدير المبلغ الإجمالي والرسوم والمرجع:
البنك + (الإجمالي − الرسوم)، ومصروف الرسوم + الرسوم، وحساب المزوّد − الإجمالي.

## المطابقة (Reconciliation)

`POST /v1/admin/finance/reconciliation` يقارن ثلاثة مصادر لفترة محددة:
**الطلبات** في ARUMA CORE، و**الدفتر المالي**، و**سجل خدمة الدفع**. يحفظ النتيجة (لا تُحذف) مع كل اختلاف:

| الفحص | ما يكشفه |
|---|---|
| `entry_balanced` | قيد غير متوازن |
| `order_paid_posted` / `order_paid_amount` | طلب مدفوع غير مسجل أو بمبلغ مختلف |
| `order_delivered_posted` | طلب مسلَّم دون قيد مبيعات وعمولة |
| `refunds_posted` / `refund_amount` | استرجاع غير مسجل أو مختلف عن خدمة الدفع |
| `cancelled_paid_not_refunded` | طلب ملغى دُفع ولم يُسترجع ماله |
| `payment_without_order` / `payment_amount` | دفعة عند المزوّد لا تطابق أي طلب |
| `cash_collected_posted` | نقد مستلم دون تسليم مسجل |
| `ledger_payment_unknown` | قيد دفع لا تعرفه خدمة الدفع |

`GET /v1/admin/finance/trial-balance` يعرض ميزان المراجعة لكل الحسابات، ومجموعه يساوي صفرًا دائمًا.

## مركز التاجر

- **الرصيد:** قيد الانتظار، المتاح، المُسوّى، الإجمالي، والمجاميع منذ البداية (مبيعات، عمولة، رسوم، استرجاعات، محوَّل)، مع كشف حساب لكل حركة.
- **التسويات والتحويلات:** القائمة مع الحالة ومرجع التحويل.
- كل ذلك **للاطلاع فقط**، ومتاح للمالك والمدير فقط (الموظف يُرفض بـ 403).

## قبل الإطلاق

1. **محاسب معتمد في الجزائر** يراجع: توقيت الاعتراف بالعمولة، الفوترة، والضرائب (TVA على العمولة، IRG/IBS). الدفتر جاهز لإضافة حسابات ضريبية دون تغيير البنية.
2. **حساب بنكي للشركة** وطريقة التحويل للتجار (تحويل بنكي/CCP يدوي في البداية). الربط الآلي مع بنك يُضاف لاحقًا عند توفر واجهة رسمية.
3. **تأكيد العمولة النهائية** (8% حاليًا) وفترة الحجز (7 أيام) ورسوم الطلب (0)، وكلها تتغير من الإدارة دون برمجة.
4. **إجراء داخلي:** شخصان لتأكيد كل دفعة للتجار (من ينفذ التحويل غير من يراجعه)، ومطابقة أسبوعية.
