# الطلبات — Orders

## طلب لكل تاجر

- إذا اشترى الزبون من عدة تجار في نفس العملية، يُنشأ **طلب منفصل لكل تاجر**، والطلبات تجمعها عملية دفع واحدة (`checkoutId`). كل تاجر يحضّر ويشحن طرده بنفسه، فلكل طلب حالته.
- **الأسعار تُحسب في الخادم دائمًا:** أي سعر يرسله المتصفح يُتجاهل. والسعر يُجمَّد في الطلب، فتغيير التاجر لسعره لاحقًا لا يغيّر الطلبات السابقة.
- **المخزون يُحجز في نفس العملية:** إذا نقص منتج واحد يُرفض الطلب كله، ولا يُنشأ شيء.
- **إعادة الإرسال آمنة:** ترويسة `Idempotency-Key` تجعل الضغط المزدوج أو انقطاع الشبكة لا يُنشئ طلبًا ثانيًا.
- **العمولة والرسوم تُحفظ في الطلب** كما كانت لحظة الشراء، وعند التسليم يُسجَّل البيع والعمولة في الدفتر المالي ([FINANCE.md](FINANCE.md)).
- **رقم الطلب** على شكل `2026-000042`.
- **التوصيل:** الزبون يختار طريقة توصيل لكل تاجر، والخادم يحسب السعر من أسعار التاجر ويحفظه في الطلب. العنوان: البلدية، والدائرة، والولاية ([SHIPPING.md](SHIPPING.md)).

## الحالات والانتقالات

```
New ──► Processing ──► Preparing ──► Shipping ──► Delivered
 │           │             │             │            │
 └───────────┴──► Cancelled              └─► Returned ◄┘
                      │                        │
                      └──────► Refunded ◄──────┘
```

| من | إلى | من يستطيع | السبب |
|---|---|---|---|
| New | Processing | التاجر، ARUMA | — (الدفع عند الاستلام: بعد تأكيد الزبون، [COD.md](COD.md)) |
| New / Processing | Cancelled | الزبون، التاجر (مالك/مدير)، ARUMA | إلزامي إلا للزبون |
| Processing | Preparing | التاجر، ARUMA | — |
| Preparing | Shipping | التاجر، ARUMA، النظام (تحديث من الناقل) | — (رقم التتبع إلزامي مع شركة توصيل) |
| Preparing | Cancelled | التاجر (مالك/مدير)، ARUMA | إلزامي |
| Shipping | Delivered | التاجر، ARUMA، النظام (تحديث من الناقل) | — |
| Shipping / Delivered | Returned | التاجر (مالك/مدير)، ARUMA | إلزامي، مع قرار إعادة البضاعة للبيع |
| Returned / Cancelled | Refunded | **تلقائيًا عند اكتمال الاسترجاع المالي** الذي يطلبه مدير ARUMA ([PAYMENTS.md](PAYMENTS.md)) | إلزامي |

- **قفزات ممنوعة:** لا يمكن مثلًا الانتقال من New إلى Delivered مباشرة.
- **الإلغاء من الزبون:** ممكن ما دام الطلب New أو Processing فقط.
- **الاسترجاع المالي:** التاجر **لا يستطيع أبدًا** تسجيل استرجاع مالي. المال من اختصاص المنصة.

## أثر الحالات على المخزون

| الحالة | المخزون |
|---|---|
| New | يُحجز (المتاح ينقص) |
| Cancelled | يُحرَّر الحجز (المتاح يعود) |
| Shipping | يُخصم نهائيًا من المستودع |
| Returned + «إعادة للبيع» | يعود إلى المستودع الافتراضي |

## السجل: كل تغيير مسجّل

كل تغيير حالة يُكتب في `order_status_history`:
- **من قام به:** زبون، تاجر، ARUMA، مع اسم المستخدم.
- **الوقت.**
- **الحالة السابقة والحالة الجديدة.**
- **السبب**، وملاحظة اختيارية مثل رقم التتبع أو قرار إعادة البضاعة.

الزبون يرى الدور فقط (تاجر أو ARUMA)، لا أسماء الموظفين.

## الحماية في قاعدة البيانات

حتى لو أخطأ الكود، أو حاول أحد التعديل مباشرة في قاعدة البيانات:
- **الانتقالات غير المسموحة تُرفض.**
- **بعد إنشاء الطلب لا يتغير إلا حالته:** المبالغ، والتاجر، والزبون، والرقم ثابتة.
- **أسطر الطلب وسجل الحالات** لا تُعدَّل ولا تُحذف.
- **الطلبات لا تُحذف.**

## الواجهات (API)

| الطريقة | المسار | من |
|---|---|---|
| POST | `/v1/stores/:storeSlug/orders` (+ ترويسة `Idempotency-Key`) | الزبون |
| GET | `/v1/me/orders`، `/v1/me/orders/:id` | الزبون |
| POST | `/v1/me/orders/:id/cancel` | الزبون |
| GET | `/v1/merchants/:merchantId/orders?status=`، `/orders/:id` | أعضاء التاجر |
| POST | `/v1/merchants/:merchantId/orders/:id/status` `{ to, reason?, note?, restock? }` | أعضاء التاجر حسب الدور |
| GET | `/v1/admin/orders`، `/v1/admin/orders/:id` | admin، support |
| POST | `/v1/admin/orders/:id/status` | admin، support (الاسترجاع المالي للمدير فقط) |

كل جواب لتفاصيل الطلب يحتوي `allowedTransitions`: الخطوات الممكنة لهذا المستخدم الآن. منها تُبنى الأزرار في الواجهة.

## ما يأتي لاحقًا
- **صفحة المتجر للزبون:** السلة وإتمام الطلب عبر الواجهة. الـAPI جاهز.
- **أسعار التوصيل حسب الولاية وشركات النقل:** وحدة التوصيل ([SHIPPING.md](SHIPPING.md)). ✅ تم
- **الدفع:** إلكتروني أو عند الاستلام، والاسترجاع المالي، عبر خدمة الدفع المستقلة ([PAYMENTS.md](PAYMENTS.md)). ✅ تم
- **طلبات الإرجاع من الزبون** مع الإثبات والفحص والحلول ([RETURNS.md](RETURNS.md)). ✅ تم
- **إشعارات SMS للزبون عند كل تغيير حالة:** تُبنى على الحدث `orders.order.status_changed` المسجّل.
