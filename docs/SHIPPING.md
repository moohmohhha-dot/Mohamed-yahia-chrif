# التوصيل — Shipping

وحدة `shipping` داخل ARUMA CORE (`apps/core/src/modules/shipping`). تغطي:
- العنوان الجزائري.
- طرق التوصيل لكل تاجر، ومناطقها وأسعارها.
- شركات التوصيل وربطها.
- الطرود وتتبّعها.
- نقاط الاستلام (مُجهّزة للمستقبل).

**لماذا ليست خدمة مستقلة؟** لا توجد حاجة تقنية حاليًا. الوحدة معزولة، ولا تتصل ببقية النظام إلا عبر `index.ts`، فيمكن فصلها لاحقًا إذا صار لـARUMA Logistics أسطول وتطبيق سائقين.

## العنوان الجزائري

| الحقل | في النظام |
|---|---|
| الولاية (Wilaya) | `regionId` + `region` (مثل `DZ-16`، الجزائر) |
| الدائرة (Daïra) | `districtId` + `district` |
| البلدية (Commune) | `cityId` + `city` |
| العنوان | `line1` (+ `line2`) |
| الهاتف | `phone` |
| ملاحظات التوصيل | `deliveryNotes` |

- **الزبون يختار البلدية فقط** (`localityId`)، والخادم يستخرج منها الدائرة والولاية. لذلك لا يمكن أن يكون العنوان متناقضًا، مثل بلدية في غير ولايتها.
- **الهاتف:** يُقبل بالصيغة المحلية `0555 12 34 56` ويُحفظ دوليًا `+213555123456`. المقبول: الأرقام النقالة 05/06/07، والثابتة 02–04.
- **العنوان يُحفظ في الطلب** كما كان لحظة الشراء.
- **البيانات المحمّلة:** 58 ولاية، و548 دائرة، و1541 بلدية، بالعربية والفرنسية.
  - المصدر: قائمة وزارة الداخلية كما نشرها المشروع المفتوح [othmanus/algeria-cities](https://github.com/othmanus/algeria-cities).
  - سكريبت التوليد: `packages/db/scripts/generate-dz-areas.py`.
- **الجداول عامة لكل الدول** (منطقة ← مقاطعة ← بلدية). إضافة المغرب أو تونس لاحقًا = بيانات فقط، دون تغيير الكود. الدول التي لا توجد بياناتها بعد تقبل المدينة والمنطقة كنص.

> **تنبيه:** إذا غيّرت الدولة التقسيم الإداري (ولايات جديدة)، يكفي ملف migration جديد بالبيانات. معرّفات المناطق الحالية لا تتغير.

## طرق التوصيل

كل تاجر يحدد كيف يوصل طلباته:

| النوع | المعنى | رقم التتبع |
|---|---|---|
| `merchant_delivery` | التاجر يوصل بنفسه أو بسائقه | غير مطلوب |
| `courier` | شركة توصيل (Yalidine، ZR Express، Maystro…) | **إلزامي** قبل خروج الطرد |
| `local_pickup` | الزبون يستلم من محل التاجر (عنوان وأوقات) | غير مطلوب |
| `pickup_point` | نقطة استلام أو مكتب شركة توصيل (Stop Desk) | إلزامي، **مُطفأة** بالعلم `shipping.pickup_points` |

- لكل طريقة خيار **«الدفع عند الاستلام مقبول»**. مثال: «توصيل سريع بالدفع الإلكتروني فقط».
- قائمة شركات التوصيل في قاعدة البيانات، والإدارة تضيف إليها:
  - المضافة حاليًا: Yalidine Express، وZR Express، وMaystro Delivery.
  - كلها في الوضع اليدوي (`manual`): التاجر يُدخل رقم التتبع ويحدّث الحالة.

## مناطق التوصيل والأسعار

- **المنطقة** مجموعة ولايات، أو دوائر، أو بلديات، يختارها التاجر. مثال: «العاصمة» = DZ-16، و«الغرب» = وهران + عين تموشنت.
- **السعر** يُحدد لكل طريقة ولكل منطقة، أو «كل الجزائر». يتضمن:
  - السعر.
  - مبلغ التوصيل المجاني (اختياري).
  - المدة (أقل وأقصى عدد أيام).
- **الأولوية للأدق:** البلدية، ثم الدائرة، ثم الولاية، ثم كل الجزائر. مثال: إذا كانت باب الوادي بـ350 دج والعاصمة بـ300 دج، فطلب باب الوادي بـ350 دج.
- إذا لم يوجد سعر لعنوان ما، لا تظهر الطريقة للزبون.
- **السعر يحسبه الخادم دائمًا.** أي سعر يرسله المتصفح يُتجاهل.
- **السعر يُحفظ في الطلب.** تغيير التاجر لأسعاره لاحقًا لا يغيّر الطلبات السابقة.
- الطلب يحفظ أيضًا الطريقة كما كانت: الاسم، والنوع، والشركة، والمدة.
- المناطق تُؤرشف ولا تُحذف.

### العمولة والتوصيل

**عمولة ARUMA تُحسب على السلع فقط**، وسعر التوصيل يذهب للتاجر لأنه هو من يدفع لشركة التوصيل أو يوصل بنفسه.

مثال: سلع بـ5,000 دج + توصيل 400 دج:
- عمولة ARUMA: 400 دج (8% من 5,000).
- مستحق التاجر: 5,000 دج.

التفاصيل في [FINANCE.md](FINANCE.md).

## الطلب: كيف يختار الزبون

1. `POST /v1/stores/:storeSlug/delivery-options` مع السلة والبلدية. النتيجة: السلة مقسمة حسب التاجر، ولكل تاجر طرق التوصيل المتاحة مع السعر والمدة.
2. `POST /v1/stores/:storeSlug/orders` مع:
   - `shippingAddress`: البلدية، والعنوان، والهاتف، والملاحظات.
   - `delivery: [{ merchantId, methodId }]`: اختيار واحد لكل تاجر.

**الأخطاء:**

| الرمز | المعنى |
|---|---|
| `LOCALITY_REQUIRED` | البلدية لم تُحدد |
| `UNKNOWN_LOCALITY` | البلدية غير موجودة |
| `INVALID_PHONE` | الهاتف غير صحيح |
| `DELIVERY_METHOD_REQUIRED` | تاجر بلا اختيار توصيل |
| `DELIVERY_UNAVAILABLE` | الطريقة لا توصل لهذا العنوان |
| `CASH_ON_DELIVERY_UNAVAILABLE` | الطريقة لا تقبل الدفع عند الاستلام |
| `PICKUP_POINT_REQUIRED` | نقطة الاستلام لم تُحدد |
| `PICKUP_POINT_TOO_FAR` | نقطة الاستلام في ولاية أخرى |

## الطرد (Shipment) وحالاته

```
pending ─► in_transit ─► out_for_delivery ─► delivered ─► returning ─► returned
   │           │   └──► delivery_failed ◄──┘  (إعادة محاولة، أو عودة للتاجر)
   │           └──► ready_for_pickup (نقطة استلام)
   ├─► ready_for_pickup ─► delivered (استُلم) / returning, returned (لم يُستلم)
   └─► cancelled (لم يخرج)
```

| الحالة | بالعربية |
|---|---|
| pending | قيد التجهيز |
| ready_for_pickup | جاهز للاستلام |
| in_transit | في الطريق (عند الناقل) |
| out_for_delivery | خرج للتوصيل |
| delivery_failed | فشل التوصيل (الزبون غائب أو لا يرد) |
| delivered | تم التسليم |
| returning | في طريق العودة |
| returned | عاد للتاجر |
| cancelled | أُلغي قبل خروجه |

**القواعد:**
- الانتقالات مفروضة في الخادم **وفي قاعدة البيانات**.
- الطرد لا يُحذف.
- لا يتغير الطلب ولا الوجهة ولا المبلغ المحصّل بعد إنشاء الطرد.
- رقم التتبع لا يتغير بعد خروج الطرد.
- **سجل التتبع** (`shipment_events`) append-only. لكل سطر:
  - المصدر: التاجر، أو الناقل، أو ARUMA، أو النظام.
  - الشخص، والوقت، والمكان، والملاحظة.
- الزبون يرى الحالات والأماكن، ولا يرى أسماء موظفي التاجر.

### الطرد والطلب يتحركان معًا

| ما يحدث للطرد | ما يحدث للطلب |
|---|---|
| التاجر يجهّز الطرد | Processing ← Preparing |
| خرج (in_transit / out_for_delivery / ready_for_pickup) | ← Shipping (يُخصم المخزون نهائيًا) |
| delivered | ← Delivered (يُسجّل البيع في الدفتر المالي، والدفع عند الاستلام يُسجّل محصّلًا) |
| returned | **لا يتغير تلقائيًا:** التاجر يؤكد الإرجاع ويقرر هل تعود السلعة للبيع |
| الطلب أُلغي قبل الخروج | الطرد ← cancelled (وإن كان مسجلًا عند الناقل بالـAPI يُسحب منه) |

التاجر يستطيع أيضًا تحريك الطلب مباشرة كما في السابق، والطرد يتبعه. لكن الطلب لا يخرج مع شركة توصيل بدون رقم تتبع.

## ربط شركات التوصيل (Courier Integration)

**المبدأ:** لا نخترع API.
- كل شركة لها **محوّل (adapter)** واحد (`modules/shipping/couriers/`) يُكتب من وثائقها الرسمية، ويُختبر بحساب اختبار حقيقي.
- قبل ذلك تعمل الشركة في **الوضع اليدوي**، وهو يعمل اليوم.

ما يقدمه الإطار الجاهز:
- **حساب الناقل:** للتاجر (عقده الخاص مع الشركة)، أو للمنصة لاحقًا (ARUMA Logistics).
  - المفاتيح **مشفّرة** (AES-256-GCM) ولا تُعاد أبدًا عبر الـAPI.
  - المالك فقط يربط الحساب.
- **إنشاء الطرد عند الناقل:** يُرسل للناقل:
  - رقم الطلب.
  - العنوان: البلدية، والدائرة، والولاية، والملاحظات.
  - المبلغ المحصّل عند الاستلام.
  - قيمة السلع.

  والناقل يعيد رقم التتبع والملصق.
- **Webhooks:** `POST /webhooks/couriers/:accountId`، رابط لكل حساب.
  - المحوّل يتحقق من التوقيع (المرفوض ← 401).
  - يترجم حالات الناقل إلى حالاتنا.
  - التحديث المكرر يُسجّل مرة واحدة.
  - التحديث المتأخر (حالة أقدم بعد التسليم) يُحفظ في السجل دون إرجاع الطرد للخلف.
- الطرد الذي يتتبعه الناقل لا يغيّر التاجر حالته يدويًا. ARUMA تستطيع التصحيح عند تعطل الناقل.
- **ناقل تجريبي (`sandbox`)** للتطوير والاختبارات فقط (`COURIER_SANDBOX=true`)، ويُرفض في الإنتاج.

### Yalidine: أول ربط مقترح

| السؤال | الجواب |
|---|---|
| **الاسم** | Yalidine Express (yalidine.com) |
| **لماذا** | من أكبر شبكات التوصيل في الجزائر (كل الولايات تقريبًا، ومكاتب Stop Desk)، ولها API للمتاجر الإلكترونية |
| **مجاني أم مدفوع** | الـAPI بلا اشتراك حسب علمنا؛ تدفع سعر التوصيل لكل طرد حسب عقدك. **يُؤكد مع Yalidine عند التسجيل** |
| **التسجيل** | فتح حساب تاجر (e-commerce) لدى Yalidine، عبر موقعهم أو أقرب مكتب |
| **مفتاح الـAPI** | من لوحة Yalidine للمحترفين: الإعدادات ← API، وفيها **API ID** و**API Token** |
| **أين تُحفظ** | لا تُوضع في الكود ولا في ملفات الإعداد. التاجر يُدخلها في ARUMA (مشفّرة)، أو تُحفظ في مدير الأسرار إن كان الحساب لـARUMA |
| **الاختبار** | بعد الحصول على الحساب ووثائق الـAPI: نكتب المحوّل، ونختبره بطرود تجريبية مع Yalidine، ثم نفعّل `integration = api` |

> **لماذا لم يُكتب محوّل Yalidine الآن؟** وثائق الـAPI الرسمية لا تُفتح إلا بعد تسجيل الدخول، ولم يكن الوصول إليها ممكنًا من بيئة العمل. كتابته دون الوثائق الرسمية يعني تخمين API، وهذا ممنوع. الوضع اليدوي يعمل بالكامل حتى ذلك الحين.

نفس الطريقة تنطبق لاحقًا على ZR Express وMaystro وغيرهما.

## نقاط الاستلام (للمستقبل)

- الجدول `pickup_points` جاهز:
  - مكتب لشركة توصيل، ولاحقًا محلات شريكة أو نقاط ARUMA.
  - البلدية، والعنوان، والأوقات، ومعرّف الناقل.
- الإدارة تضيف النقاط (`POST /v1/admin/pickup-points`)، والزبون يرى نقاط ولايته (`GET /v1/pickup-points?regionId=DZ-16`).
- طريقة `pickup_point` لا تظهر للزبون حتى يُفعّل العلم `shipping.pickup_points` للمتجر.
- عند التفعيل يختار الزبون نقطة في ولايته، وتُحفظ في الطلب.

## مركز التاجر

- **قسم «التوصيل»:**
  - مناطق التوصيل (اختيار الولايات).
  - طرق التوصيل: توصيل بنفسي، أو شركة توصيل، أو استلام من المحل.
  - الأسعار لكل منطقة، مع التوصيل المجاني والمدة.
  - المالك والمدير يعدّلان، والموظف يطّلع فقط.
- **صفحة الطلب:**
  - البلدية والدائرة والولاية، وملاحظات التوصيل.
  - طريقة التوصيل.
  - لوحة الطرد: تجهيز، ورقم التتبع، والحالات، والمبلغ المحصّل، وسجل التتبع غير القابل للتعديل.

## الواجهات (API)

**عامة:**

| الطريقة | المسار |
|---|---|
| GET | `/v1/geo/DZ/areas` (الولايات)، و`?parentId=DZ-16` (الدوائر)، و`?parentId=<دائرة>` (البلديات) |
| GET | `/v1/couriers?country=DZ` |
| GET | `/v1/pickup-points?regionId=…&courierCode=…` |
| POST | `/v1/stores/:storeSlug/delivery-options` |

**التاجر:**

| الطريقة | المسار | من |
|---|---|---|
| GET | `/v1/merchants/:id/shipping` | كل الأعضاء |
| POST / PUT / DELETE | `/v1/merchants/:id/shipping/zones[/:zoneId]` | مالك، مدير |
| POST / PUT | `/v1/merchants/:id/shipping/methods[/:methodId]` | مالك، مدير |
| PUT / DELETE | `/v1/merchants/:id/shipping/methods/:methodId/rates[/:rateId]` | مالك، مدير |
| POST / DELETE | `/v1/merchants/:id/shipping/courier-accounts[/:accountId]` | المالك فقط |
| POST | `/v1/merchants/:id/orders/:orderId/shipment` | كل الأعضاء |
| POST | `/v1/merchants/:id/orders/:orderId/shipment/status` | كل الأعضاء |

**الإدارة:**

| الطريقة | المسار |
|---|---|
| POST / PATCH | `/v1/admin/couriers[/:code]` |
| POST / PATCH | `/v1/admin/pickup-points[/:pointId]` |
| POST | `/v1/admin/orders/:orderId/shipment/status` (تصحيح، مع ملاحظة إلزامية) |

**الناقلون:** `POST /webhooks/couriers/:accountId` (موقّع).

## قبل الإطلاق

1. **حساب تاجر لدى Yalidine** (أو الشركة التي تختارها)، ثم وثائق الـAPI ومفاتيح الاختبار، لنكتب المحوّل ونختبره. حتى ذلك الحين يعمل كل شيء يدويًا.
2. **أسعار حقيقية:** كل تاجر يُدخل أسعاره. الأسعار في البيانات التجريبية للتاجر الافتراضي (400 دج للعاصمة و700 لباقي الجزائر) أمثلة فقط.
3. **مراجعة قائمة البلديات** إذا صدر تقسيم إداري جديد.
4. **عنوان HTTPS عام** لاستقبال webhooks الناقلين.
