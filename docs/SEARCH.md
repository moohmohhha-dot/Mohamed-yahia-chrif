# البحث — ARUMA Search

محرك بحث واحد لكل متاجر ARUMA، يفهم **العربية والفرنسية والإنجليزية**، ويصحّح الأخطاء، ويعرف المرادفات، ويقترح أثناء الكتابة.
مبني داخل PostgreSQL نفسها: **لا خدمة خارجية، لا اشتراك، لا مفاتيح**. ومُصمَّم لكي يُستبدل أو يُكمَّل لاحقًا (بحث صوتي، لغة طبيعية، ذكاء اصطناعي، محرك مستقل) دون تغيير واجهة المتجر.

## ما الذي يظهر في البحث

منتج يظهر فقط إذا كان **قابلًا للبيع الآن**:
- المنتج نشط وغير محظور من ARUMA، والمتجر نشط؛
- له عرض واحد على الأقل من تاجر **نشط وموثَّق** ومرتبط بالمتجر، ومتغيّر نشط، وسعر بعملة الزبون.

المسودات، والمنتجات المحظورة، ومنتجات تاجر موقوف تختفي من البحث تلقائيًا خلال ثوانٍ. البحث لا يمر عبر أي مال ولا يغيّر أي سجل.

## كيف يعمل

```
تغيير (منتج، ترجمة، عرض، سعر، تقييم، تاجر، علامة، تصنيف)
   → مُشغِّل (trigger) في قاعدة البيانات يضع المنتج في search_queue
   → المفهرس (كل 5 ثوانٍ) يبني صفًا واحدًا لكل منتج في search_documents
   → البحث يقرأ search_documents فقط (سريع، بلا ربط جداول)
```

- `search_documents`: نسخة مسطّحة لكل منتج: الأسماء بكل اللغات، العلامة، التصنيفات **مع آبائها** (البحث في «عطور» يجد «عطور شرقية»)، التجار، أقل سعر لكل عملة، التوفر، متوسط التقييم وعدده، الشعبية (المبيعات في 90 يومًا)، ونص البحث (tsvector) بأوزان: الاسم أولًا، ثم العلامة والتصنيف، ثم الوصف والنفحات.
- كل ليلة: إعادة فهرسة كاملة (احتياط)، وحذف سجل عمليات البحث الأقدم من 180 يومًا.
- `search_terms`: مفردات كل متجر (من أسماء منتجاته الظاهرة)؛ منها يأتي تصحيح الأخطاء والإكمال التلقائي.
- الامتداد `pg_trgm` (مدمج في PostgreSQL، مجاني) للتشابه بين الكلمات.

## اللغات

قبل الفهرسة وقبل البحث، يُوحَّد النص (`normalize.ts`):

| ما يُوحَّد | مثال |
|---|---|
| التشكيل والتطويل | «عُودٌ مَلَكِي» = «عود ملكي»، «عطــــر» = «عطر» |
| الهمزات والتاء المربوطة والألف المقصورة | «أُود» = «اود»، «زهرة» = «زهره» |
| «ال» والحروف الملتصقة بها | «بالعود» = «عود»، «للرجال» = «رجال» |
| الأرقام العربية | «٨٠٠٠» = «8000» |
| الحروف الفرنسية | «Boisé Œillet» = «boise oeillet» |
| الكلمات الشائعة | «un parfum pour la fête» → «parfum fete» |

ثم يُطابَق كل كلمة بثلاث طرق معًا: البادئة (للكتابة الجارية: «jasm» تجد «jasmin»)، والجذر بالعربية أو الفرنسية أو الإنجليزية («fleurs» تجد «fleur»)، والمرادفات.

## المرادفات

مجموعات كلمات بنفس المعنى بأي لغة: البحث عن إحداها يجد الأخرى. «مسك» يجد «Musc Blanc»، و«agarwood» يجد «عود».
- 17 مجموعة جاهزة للعطور: عطر، عود، مسك، عنبر، ورد، ياسمين، فانيليا، زعفران، خشب، زهري، منعش، شرقي، بحري، رجالي، نسائي، هدية، كولونيا.
- فريق المحتوى يضيف أو يحذف مجموعات من لوحة الإدارة (قسم «البحث»)، لكل المتاجر أو لمتجر واحد. كل تغيير في سجل التدقيق، ويُطبَّق خلال دقيقة على الأكثر.
- أفضل مصدر لمرادفات جديدة: قائمة «بُحث عنها ولم توجد» في نفس القسم.

## تصحيح الأخطاء

إذا لم يجد البحث شيئًا، تُصحَّح كل كلمة إلى أقرب كلمة في مفردات المتجر ويُعاد البحث، ويُعاد للواجهة `correctedFrom` لتعرض «نتائج لـ jasmin بدل jasmn».
إذا وُجدت نتائج قليلة وكان التصحيح يجد أكثر، تُعاد `suggestion` («هل تقصد…؟») دون تغيير النتائج.

## الفلاتر والترتيب

| الفلتر | المعامل |
|---|---|
| العلامة | `brand=slug1,slug2` |
| التصنيف (مع تصنيفاته الفرعية) | `category=slug` |
| التاجر | `merchant=slug` |
| السعر (بالوحدة الكاملة للعملة) | `priceMin`, `priceMax` |
| التقييم | `ratingMin=4` |
| المتوفر فقط | `inStock=true` |
| خصائص العطر | `gender=men|women|unisex`, `concentration=EDP|EDT|…` |

الترتيب `sort`: `relevance` (الافتراضي: تطابق النص + التشابه + الشعبية)، `price_asc`, `price_desc`, `rating`, `newest`, `popular`.
بدون كلمات بحث، القائمة مرتبة بالشعبية. مع النتائج تأتي `facets`: عدد المنتجات لكل علامة وتصنيف وتاجر وجنس، ونطاق الأسعار، وعدد ما فوق 4 و3 نجوم.

## فهم الجمل (اللغة الطبيعية)

الزبون يكتب كما يتكلم، والبحث يستخرج الفلاتر:

| ما يكتبه الزبون | ما يُفهم |
|---|---|
| «عطر رجالي أقل من 8000 دج» | عطر + رجالي + السعر ≤ 8000 |
| «parfum femme entre 5 000 et 9 000 DA» | parfum + نسائي + 5000–9000 |
| «cheapest unisex perfume in stock» | perfume + للجنسين + متوفر + الأرخص أولًا |
| «oud 4 étoiles et plus» | oud + تقييم ≥ 4 |
| «عود أقل من 9 آلاف» | عود + السعر ≤ 9000 |

- القواعد في `interpret.ts`، خلف واجهة `QueryInterpreter`؛ ما فُهم يُعاد في `understood` لتعرضه الواجهة كفلاتر يمكن إزالتها.
- الفلتر الذي يختاره الزبون صراحةً يتقدم دائمًا على ما فُهم من الجملة. `understand=false` يوقف الفهم.

## الإكمال التلقائي

`GET /v1/stores/:slug/search/suggest?q=…` يعيد أثناء الكتابة: عمليات بحث شائعة لها نتائج، إكمال الكلمة (مع تصحيح الأخطاء)، منتجات، علامات، تصنيفات.

## الواجهات (API)

| الطلب | الوصف |
|---|---|
| `GET /v1/stores/:slug/search?q=&locale=&currency=&…&sort=&page=&pageSize=&source=` | البحث (حتى 48 نتيجة في الصفحة). `source`: `text` أو `voice` |
| `GET /v1/stores/:slug/search/suggest?q=&locale=` | الإكمال التلقائي (240 طلبًا في الدقيقة) |
| `GET /v1/admin/search/status` | حالة الفهرس (`search.manage` أو `analytics.read`) |
| `GET /v1/admin/search/analytics?days=30` | الأكثر بحثًا، بلا نتائج، نسبة البحث الصوتي |
| `POST /v1/admin/search/reindex` | إعادة فهرسة الكل (`search.manage`، في سجل التدقيق) |
| `GET/POST/DELETE /v1/admin/search/synonyms` | المرادفات (`search.manage`، في سجل التدقيق) |

الرد: `{ data: { query: { text, words, correctedFrom, suggestion, understood, sort }, results: […], facets: {…}, meta: { total, page, pageSize, totalPages, locale, currency } } }`.

## الخصوصية والأمان

- سجل البحث (`search_queries`) يحفظ النص الموحَّد وعدد النتائج والمصدر **فقط**: لا مستخدم، لا IP. يُحذف بعد 180 يومًا.
- كل نص من الزبون يمر كمعامل في الاستعلام (لا SQL مُركَّب)؛ حتى 12 كلمة، والعلامات الخاصة تُحذف. الاختبارات تتحقق من نصوص عدائية.
- الصلاحية `search.manage` لمسؤول المحتوى والمدير العام؛ الإحصاءات أيضًا لمن لديه `analytics.read`.

## التحضير للمستقبل

البحث جاهز الآن لما يلي، دون أي مزوّد خارجي. **لا شيء منه مُفعَّل اليوم، ولا مفاتيح مطلوبة.**

### البحث الصوتي
- الواجهة تحوّل الصوت إلى نص، ثم تستدعي نفس البحث مع `source=voice` (يظهر في الإحصاءات). الخادم لا يستقبل الصوت أبدًا.
- الخيار الأول، **مجاني ودون تسجيل**: التعرّف على الكلام المدمج في المتصفح (Web Speech API) أو في الهاتف (Android SpeechRecognizer / iOS Speech). دعم العربية الجزائرية يختلف حسب الجهاز، ويُختبر على أجهزة حقيقية قبل الإطلاق.
- إن لم تكفِ الدقة: مزوّد تحويل كلام مدفوع (Speech-to-Text). عند الاختيار نوثّق: الاسم، السبب، السعر، التسجيل، المفاتيح (في مدير الأسرار، لا في الكود)، والاختبار — كما في [PAYMENTS.md](PAYMENTS.md).

### البحث بالجمل (اللغة الطبيعية)
- يعمل اليوم بالقواعد (أعلاه). لإضافة صيغ جديدة: قاعدة + اختبار في `interpret.ts`.

### البحث بالذكاء الاصطناعي
- **فهم أعمق للجملة**: كتابة `QueryInterpreter` جديد يستدعي نموذج لغة (مثل Claude API، مدفوع حسب الاستعمال، المفتاح من console.anthropic.com يوضع في مدير الأسرار)، ويعيد نفس الشكل `Interpretation`. مع حد زمني والرجوع للقواعد عند أي فشل، فلا يتوقف البحث أبدًا.
- **البحث بالمعنى** («عطر للسهرات الشتوية»): امتداد `pgvector` (مجاني، داخل PostgreSQL) بعمود embedding في `search_documents`، يملؤه المفهرس من مزوّد embeddings يُختار ويوثَّق عندها، ويُدمج ترتيبه مع الترتيب الحالي.
- **محرك مستقل** (مثل Meilisearch أو Typesense أو OpenSearch، مفتوحة المصدر): فقط عند الحاجة الحقيقية (كتالوج ضخم أو بطء ملحوظ). يتغذّى من نفس `search_queue`، والواجهة `/search` لا تتغير.

## التشغيل

- المفهرس يعمل داخل `apps/core` (كل 5 ثوانٍ + كل ليلة)، لا خدمة إضافية.
- بعد تغيير قواعد التوحيد أو الأوزان: «إعادة فهرسة الكل» من اللوحة أو `POST /v1/admin/search/reindex`.
- الاختبارات: `apps/core/test/search.test.ts` (اللغات، المرادفات، الأخطاء، الفلاتر، الترتيب، الجمل، الصوت، الإكمال، الصلاحيات، النصوص العدائية)، وفحص اللوحة في `apps/admin/e2e`.
