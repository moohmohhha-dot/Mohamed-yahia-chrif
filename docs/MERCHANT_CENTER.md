# مركز التاجر — Merchant Center

واجهة ويب للتاجر (`apps/merchant-center`) بالعربية والفرنسية والإنجليزية، تدعم الكتابة من اليمين لليسار، وتعمل فوق ARUMA CORE.

## الأقسام العشرون

| المجموعة | القسم | الحالة |
|---|---|---|
| نظرة عامة | Dashboard | ✅ حالة الحساب، المنتجات، العروض، المخزون المنخفض والنافد، المتاجر والعمولة، آخر تغييرات المخزون |
| الكتالوج | Products | ✅ إنشاء عطر (مسودة) بأسمائه في كل لغة، التصنيف، النفحات، التركيز، الأحجام؛ نشر، إرجاع إلى مسودة، أرشفة |
| | Variants | ✅ كل الأحجام، تفعيل وتعطيل، حالة العرض والمخزون |
| | Offers | ✅ البحث في منتجاتك أو منتجات السوق، السعر لكل عملة، السعر القديم، المخزون، إيقاف البيع |
| | Inventory | ✅ تعديل المخزون مع سبب وملاحظة، وسجل كامل لا يمكن تعديله |
| المبيعات | Orders, Sales, Customers | ⏳ المرحلة 1 |
| التسويق | Coupons, Promotions | ⏳ المرحلة 2 |
| | Ads | ⏳ المرحلة 3 |
| التحليل | Analytics, Reviews | ⏳ المرحلة 2 |
| التواصل | Messages, Support | ⏳ المرحلة 2 |
| المالية | Balance, Settlements | ⏳ المرحلة 2 (للاطلاع فقط) |
| | Payouts | ✅ حساب السحب وحالة توثيقه؛ سجل التحويلات في المرحلة 2 |
| الحساب | Verification | ✅ التحققات الخمسة: رموز الهاتف والبريد، الهوية، العنوان، النشاط، حساب السحب، رفع الوثائق، الإرسال للمراجعة |
| | Settings | ✅ ملف المتجر، الفريق والأدوار، المتاجر والعمولة (للاطلاع فقط) |

الأقسام المؤجلة تظهر في القائمة بعلامة «قريبًا»، وتشرح ما ستحتويه ومتى. **لا توجد فيها بيانات وهمية.**

## ما لا يستطيع التاجر فعله، وكيف نمنعه

كل قاعدة مفروضة في **الخادم** (وبعضها في **قاعدة البيانات نفسها**)، وليس فقط بإخفاء زر في الواجهة.

| القاعدة | كيف تُفرض | الاختبار |
|---|---|---|
| لا يغيّر عمولة ARUMA | لا يوجد أي مسار للتاجر يكتب العمولة؛ المسار الوحيد للمدير (`/v1/admin/...`)؛ الحقول الإضافية في الطلبات تُحذف قبل المعالجة | `merchant-center.test.ts` › cannot change the ARUMA commission |
| لا يصل إلى تاجر آخر | كل مسار `/v1/merchants/:id/...` يتحقق من العضوية؛ اختبار آلي يجرّب **كل** مسارات التاجر بحساب تاجر آخر ويتأكد أنها كلها مرفوضة | cannot reach another merchant through any merchant route |
| لا يعدّل منتجات غيره | التعديل مسموح فقط على المنتجات التي أنشأها؛ غير ذلك يُرد بـ «غير موجود» | cannot edit another merchant's products |
| لا يعدّل أو يحذف السجلات الحساسة | سجل التدقيق وسجل حركات المخزون **append-only بقاعدة البيانات**: أي UPDATE أو DELETE أو TRUNCATE يُرفض حتى لو حاول الكود نفسه ذلك؛ ولا يوجد مسار حذف للعروض أو المنتجات أو السجلات | cannot rewrite or delete history |
| لا يتلاعب بالمخزون | كل تغيير يمر عبر حركة مسجّلة (من، متى، لماذا، الكمية بعدها)، ولا ينزل تحت الصفر؛ حركة «بيع» يكتبها نظام الطلبات فقط | adjusts stock with a reason and keeps a history |
| لا يعدّل الطلبات بطريقة غير مصرّح بها / لا يتجاوز نظام الدفع / لا يتلاعب بالنقاط | الوحدات غير مبنية بعد. عند بنائها: حالة الطلب تتغير فقط عبر انتقالات محددة في الخادم، وحالة الدفع لا يغيّرها إلا مزوّد الدفع، ودفتر النقاط والدفتر المالي append-only بنفس آلية قاعدة البيانات | — |

## التشغيل

```bash
pnpm dev             # ARUMA CORE على :3000
pnpm dev:merchant    # مركز التاجر على http://localhost:5173
```

## اختبار المتصفح الكامل

```bash
DATABASE_URL=postgres://aruma:aruma@localhost:5432/aruma pnpm e2e:merchant
```

يشغّل الخادم والواجهة ومتصفح Chromium، ويمرّ بالخطوات التالية:
- تسجيل تاجر جديد بالعربية، وإنشاء متجره.
- تأكيد الهاتف بالرمز.
- ملء الهوية والعنوان، ورفع الوثائق، وإرسالها للمراجعة.
- قبول التاجر من طرف فريق المنصة.
- إنشاء عطر ونشره.
- إنشاء عرض بسعر بالدينار.
- تعديل المخزون.
- التأكد أن العطر ظاهر في MB Parfum، وأن العمولة للاطلاع فقط.

تُحفظ الصور في `apps/merchant-center/e2e/screenshots/`.
