# التقييمات — Reviews

وحدة `reviews` داخل ARUMA CORE (`apps/core/src/modules/reviews`).

## ما يدعمه النظام

| العنصر | التفاصيل |
|---|---|
| **تقييم المنتج** (Product Review) | تقييم لمنتج اشتراه الزبون من طلب معيّن. يظهر في صفحة المنتج مع اسم البائع. |
| **تقييم التاجر** (Merchant Review) | تقييم لتجربة الشراء من بائع: التوصيل، والتواصل، والتغليف. يظهر في صفحة البائع. |
| **شراء مؤكد** (Verified Purchase) | **لا يُكتب أي تقييم دون طلب حقيقي مُسلَّم** للزبون نفسه، خلال 90 يومًا من التسليم. طلب الاستبدال المجاني لا يُعتبر شراءً جديدًا. كل تقييم يحمل علامة «شراء مؤكد». |
| **التقييم** (Rating) | من 1 إلى 5 نجوم، إلزامي. المتوسط والعدد والتوزيع يُحسب من التقييمات المنشورة فقط. |
| **النص** (Text) | عنوان (اختياري، 120 حرفًا) ونص (اختياري، 10 إلى 3000 حرف). |
| **صور وفيديو** (مستقبلًا) | الجدول `review_media` جاهز، والعلم `reviews.media` **مُطفأ**. عند تفعيله تُقبل الصور (JPEG/PNG/WebP، 5 كحد أقصى، 8 ميغابايت)، مشفّرة، و**كل تقييم بصورة يمر على المراجعة** قبل ظهوره. الفيديو مُعدّ في البنية (`kind: video`). |
| **مفيد** (Helpful) | تصويت واحد لكل مستخدم، يمكن سحبه. |
| **الإبلاغ** (Report) | بلاغ واحد لكل مستخدم لكل تقييم، مع سبب: مزيف، رسائل مزعجة، مسيء، معلومات شخصية، خارج الموضوع، كتبه منافس، آخر. |
| **المراجعة** (Moderation) | فريق ARUMA (الدعم والمدير): نشر، رفض (الكاتب يرى السبب)، إخفاء، إعادة. كل قرار بملاحظة إلزامية ويُسجَّل. |
| **رد التاجر** | المالك أو المدير يرد علنًا تحت التقييم. |

## الحالات

```
(تقييم جديد) ─ فحص تلقائي ─► منشور
                       └─ علامة مشبوهة ─► قيد المراجعة ─► منشور / مرفوض
منشور ─ 3 بلاغات من مشترين مختلفين ─► قيد المراجعة
منشور ─ قرار ARUMA ─► مخفي ─► (إعادة) منشور
الكاتب: يعدّل (يُفحص من جديد) أو يسحب تقييمه
```

## الحماية من التقييمات المزيفة والرسائل المزعجة والتلاعب

### 1. لا تقييم دون شراء حقيقي
- التقييم مرتبط بطلب **مُسلَّم** للزبون نفسه.
- التقييم المزيف يحتاج إذن طلبًا حقيقيًا يُدفع ويُسلَّم وتؤخذ عليه عمولة. هذا مكلف ويترك أثرًا.
- **صوت واحد:** تقييم واحد لكل زبون لكل منتج، وواحد لكل بائع. الشراء مرة أخرى لا يعطي تقييمًا ثانيًا (الزبون يعدّل تقييمه).

### 2. تضارب المصالح
- **فريق التاجر** (المالك والمدير والموظف) لا يستطيع تقييم متجره أو منتجاته، ولا التصويت «مفيد» على تقييماتها.
- **مشترٍ هاتفه هو هاتف التاجر أو أحد موظفيه** (التاجر يشتري من نفسه بحساب آخر): يُعلَّق تقييمه للمراجعة (`merchant_contact`).
- التاجر لا يستطيع حذف التقييمات ولا تعديلها ولا إخفاءها. بلاغه وحده لا يُخفي أي تقييم: يُرسل لـARUMA فقط.

### 3. فحص تلقائي قبل النشر
أي علامة من هذه تجعل التقييم «قيد المراجعة» بدل النشر:

| العلامة | ما تكشفه |
|---|---|
| `link` | روابط لمواقع أخرى (تحويل الزبائن) |
| `contact_info` | أرقام هاتف (جزائرية أو دولية) أو بريد إلكتروني. أرقام الطلبات والكميات والتواريخ **لا** تُعتبر هاتفًا |
| `spam_pattern` | حروف مكررة بشكل غير طبيعي |
| `blocked_term` | كلمات تستدعي نظرة بشرية (احتيال، واتساب، تلغرام…). القائمة قصيرة وتُوسّع حسب الحاجة |
| `duplicate_text` | نفس النص مستعمل في تقييم آخر خلال 90 يومًا (تقييمات منسوخة) |
| `burst` | 5 تقييمات أو أكثر على نفس المنتج أو البائع خلال 24 ساعة (حملة منظمة) |
| `merchant_contact` | المشتري يستعمل هاتف التاجر أو فريقه |
| `reported` | 3 بلاغات من مشترين مختلفين |
| `media` | صورة مضافة (تُراجع دائمًا) |

### 4. حدود الاستعمال
- 10 تقييمات كحد أقصى لكل زبون في اليوم.
- 60 تصويتًا «مفيد» كحد أقصى لكل مستخدم في الساعة.
- البلاغات من حسابات **بلا أي طلب مُسلَّم** لا تُحسب في الإخفاء التلقائي، فلا يمكن إسقاط تقييم بحسابات وهمية. هذه البلاغات تُراجع يدويًا.

### 5. أثر كل شيء
- كل إنشاء، وتعديل (مع النسخة السابقة)، وتعليق، وقرار، وبلاغ، ورد يُسجَّل في `review_events`. هذا السجل append-only.
- التقييمات والبلاغات لا تُحذف.
- الكاتب والهدف والشراء لا يمكن تغييرها (محمي في قاعدة البيانات).
- تغيير التقييم بعد ضغط من التاجر يبقى ظاهرًا لـARUMA في السجل.

### 6. الخصوصية
- الاسم العلني مختصر (مثل «Yacine M.»).
- لا هاتف ولا عنوان.

## التقييم في صفحة المنتج

`GET /v1/stores/:slug/products/:productSlug` يرجع `rating: { count, average, distribution }` من التقييمات المنشورة.

## الواجهات (API)

**عامة:**

| الطريقة | المسار |
|---|---|
| GET | `/v1/products/:productId/reviews?sort=recent\|helpful\|rating_high\|rating_low&rating=` |
| GET | `/v1/sellers/:sellerId/reviews` |

**الزبون:**

| الطريقة | المسار |
|---|---|
| GET | `/v1/me/reviews`: تقييماتي، وسبب الرفض، وما يمكنني تقييمه |
| POST | `/v1/me/reviews` `{type: product, orderLineId \| type: merchant, orderId, rating, title?, body?}` |
| PATCH / DELETE | `/v1/me/reviews/:id` (تعديل / سحب) |
| POST | `/v1/me/reviews/:id/media` (عند تفعيل الصور) |
| POST / DELETE | `/v1/reviews/:id/helpful` |
| POST | `/v1/reviews/:id/report` `{reason, note?}` |

**التاجر:**

| الطريقة | المسار | من |
|---|---|---|
| GET | `/v1/merchants/:id/reviews?type=` | كل الأعضاء |
| POST | `/v1/merchants/:id/reviews/:reviewId/reply` `{text}` | مالك، مدير |
| POST | `/v1/merchants/:id/reviews/:reviewId/report` `{reason}` | مالك، مدير |

**ARUMA:**

| الطريقة | المسار |
|---|---|
| GET | `/v1/admin/reviews?status=pending&reported=true` (قائمة المراجعة) |
| GET | `/v1/admin/reviews/:id` (العلامات، والبلاغات، والسجل، والكاتب) |
| POST | `/v1/admin/reviews/:id/moderate` `{action: publish\|reject\|hide\|restore, note}` |

## قبل الإطلاق

1. **سياسة التقييمات المكتوبة:** ما هو مسموح وممنوع، ومنع التقييمات المدفوعة أو المقابل (خصم مقابل تقييم 5 نجوم)، وعقوبات التجار المخالفين.
2. **فريق مراجعة** يتابع قائمة «قيد المراجعة» يوميًا. صفحة المراجعة في لوحة إدارة ARUMA تأتي لاحقًا؛ اليوم عبر الـAPI.
3. **قائمة الكلمات الممنوعة:** توسيعها بالعربية والدارجة والفرنسية حسب ما يظهر فعلًا.
4. **الصور والفيديو:** تفعيل `reviews.media` بعد تجهيز المراجعة البصرية والتخزين السحابي.
