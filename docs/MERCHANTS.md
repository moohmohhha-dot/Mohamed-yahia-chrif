# نظام التجار — Merchant System

## نوعان من التجار

| | تاجر فرد (Individual) | تاجر شركة (Business) |
|---|---|---|
| الاسم التجاري، الهاتف، البريد | ✅ | ✅ |
| الهوية | هوية الشخص نفسه | هوية الممثل القانوني |
| العنوان | عنوان الشخص | عنوان الشركة المسجّل |
| وسيلة السحب (حساب بنكي أو بريدي) | ✅ | ✅ |
| بيانات الشركة (الاسم القانوني، الشكل القانوني، RC، NIF، NIS، رقم المادة) | — | ✅ |
| بيانات النشاط (رمز النشاط + وصفه) | ✅ | ✅ |
| **السجل التجاري** | **غير إلزامي افتراضيًا** (انظر أسفله) | إلزامي |

## خمس عمليات تحقق منفصلة

كل تحقق مستقل عن الآخر: له حالته، وملاحظة المراجِع، وتاريخه، ومن راجعه.

| التحقق | كيف يتم | ماذا يلزم |
|---|---|---|
| **Phone Verification** | رمز من 6 أرقام يُرسل بـ SMS | رقم هاتف التاجر |
| **Email Verification** | رمز من 6 أرقام يُرسل بالبريد | بريد التاجر |
| **Identity Verification** | يرسله المالك ← يراجعه فريق المنصة | الاسم الكامل، تاريخ الميلاد، الجنسية، نوع ورقم الوثيقة، صورة الوجه الأمامي (والخلفي إلا لجواز السفر)، والعنوان للفرد |
| **Business Verification** | يرسله المالك ← يراجعه فريق المنصة | للشركة: البيانات القانونية + السجل التجاري + بطاقة NIF + العنوان. للفرد (عند اللزوم): رقم التسجيل + وثيقته (سجل تجاري، بطاقة مقاول ذاتي، أو سجل الحرفيين) |
| **Payout Verification** | يرسله المالك ← يراجعه فريق المنصة | صاحب الحساب، رقم الحساب (RIB / RIP / IBAN)، إثبات الحساب |

### حالات التحقق
- **Unverified**: لم يُطلب بعد، أو رُفض (مع سبب الرفض)، أو تغيّرت بياناته.
- **Under Review**: أُرسل وينتظر مراجعة فريق المنصة.
- **Verified**: مقبول.
- **Suspended**: موقوف من طرف المنصة (مثلًا حساب بنكي مشبوه).

### الحالة العامة للتاجر تُحسب تلقائيًا
- **Suspended**: التاجر موقوف من المنصة، أو أحد تحققاته المطلوبة موقوف.
- **Verified**: كل التحققات المطلوبة مقبولة. عندها فقط يستطيع البيع.
- **Under Review**: تحقق مطلوب واحد على الأقل قيد المراجعة.
- **Unverified**: غير ذلك.

التحققات المطلوبة:
- **الفرد**: الهاتف، البريد، الهوية، السحب. ويُضاف تحقق النشاط التجاري فقط إذا فرضته قاعدة قانونية.
- **الشركة**: التحققات الخمسة.

## السجل التجاري للأفراد: قاعدة قابلة للتعديل

افتراضيًا **لا يُطلب** من الفرد أي سجل تجاري.
إذا كان القانون يفرضه في بلد معيّن لنشاط معيّن، يضيف مدير المنصة قاعدة **دون أي تعديل في الكود**:

```
PUT /v1/admin/merchant-activity-rules/DZ/perfume_retail
{ "individualRequiresRegistration": true, "note": "…المرجع القانوني…" }
```

عندها:
- يصبح تحقق النشاط مطلوبًا من الأفراد في ذلك النشاط.
- تُعاد حسابات حالة التجار الأفراد الحاليين فورًا.
- يمكن للفرد استعمال **بطاقة المقاول الذاتي** أو **سجل الحرفيين** بدل السجل التجاري.

> ⚠️ **للمراجعة القانونية قبل الإطلاق:** قانون التجارة الإلكترونية الجزائري (18-05) يشترط على المورِّد الإلكتروني
> التسجيل في السجل التجاري أو سجل الصناعات التقليدية والحرف، وقد يُقبل نظام المقاول الذاتي حسب الحالة.
> لم نضع هذه القاعدة تلقائيًا. القرار لك بعد استشارة مختص قانوني، وتفعيلها يتم بالأمر أعلاه.

## حماية البيانات الحساسة

- **رقم الوثيقة ورقم الحساب مشفّران** في قاعدة البيانات (AES-256-GCM)، ويظهر للتاجر آخر 4 أرقام فقط.
- **ملفات الوثائق مشفّرة** على القرص.
- **نوع الملف يُفحص من محتواه الحقيقي**: PDF وJPEG وPNG وWebP فقط، وحد أقصى 10 ميغابايت.
- **صلاحيات الهوية والسحب**: بياناتهما ووثائقهما للمالك فقط، وليس للمدير أو الموظف.
- **فريق المنصة** (admin/support) يرى الأرقام كاملة لمراجعتها، وكل اطلاع يُسجَّل في سجل التدقيق.
- **رموز الهاتف والبريد**:
  - تُحفظ مشفّرة (hash) وتنتهي بعد 10 دقائق.
  - 5 محاولات كحد أقصى لكل رمز.
  - رمز جديد مرة واحدة في الدقيقة.
- **أي تعديل على بيانات تحقق مقبول** (الهوية، الحساب، الهاتف، وثيقة…) يعيد ذلك التحقق إلى Unverified، ويتوقف البيع حتى يُعاد قبوله.
- **الإيقاف لا يُرفع بتعديل البيانات**: فقط فريق المنصة يرفعه.
- **مفتاح التشفير** `DATA_ENCRYPTION_KEY`:
  - يجب حفظه في مكان آمن مع نسخة احتياطية.
  - ضياعه يعني ضياع البيانات المشفّرة.

## الواجهات (API)

### التاجر
| الطريقة | المسار | من |
|---|---|---|
| POST | `/v1/merchants` | أي مستخدم (`type`: individual أو business) |
| PATCH | `/v1/merchants/:id` | المالك/المدير: الاسم، النشاط، الهاتف، البريد |
| GET | `/v1/merchants/:id/profile` | المالك/المدير: الملف كاملًا مع إخفاء الأرقام |
| PUT | `/v1/merchants/:id/address` | المالك/المدير |
| PUT | `/v1/merchants/:id/identity` | المالك |
| PUT | `/v1/merchants/:id/business` | المالك |
| PUT | `/v1/merchants/:id/payout-method` | المالك |
| POST | `/v1/merchants/:id/documents?kind=…` | المالك (والمدير لوثائق النشاط) |
| GET | `/v1/merchants/:id/documents/:docId/file` | المالك (والمدير لوثائق النشاط) |
| GET | `/v1/merchants/:id/verification` | الأعضاء: الحالة وما ينقص كل تحقق |
| POST | `/v1/merchants/:id/verifications/{identity,business,payout}/submit` | المالك |
| POST | `/v1/merchants/:id/verifications/{phone,email}/send-code` | المالك/المدير |
| POST | `/v1/merchants/:id/verifications/{phone,email}/confirm` | المالك/المدير |

### فريق المنصة
| الطريقة | المسار | من |
|---|---|---|
| GET | `/v1/admin/merchants?checkUnderReview=identity` | admin, support: قائمة المراجعة |
| GET | `/v1/admin/merchants/:id` | admin, support: الملف كاملًا (مُسجَّل في التدقيق) |
| GET | `/v1/admin/merchants/:id/documents/:docId/file` | admin, support (مُسجَّل في التدقيق) |
| POST | `/v1/admin/merchants/:id/verifications/:kind` | admin: `approve` / `reject` / `suspend` / `reinstate` |
| POST | `/v1/admin/merchants/:id/suspend` و`/unsuspend` | admin |
| PUT | `/v1/admin/merchant-activity-rules/:country/:activity` | admin |

## ما ينقص قبل الإطلاق الفعلي
- **مزوّد SMS وبريد حقيقي.** حاليًا تُكتب الرموز في سجل الخادم (للتطوير فقط)، والخادم يرفض التشغيل في وضع الإنتاج إلى أن يُضاف مزوّد.
- **تخزين سحابي للوثائق** (S3 أو ما يشبهه). الواجهة جاهزة، والتخزين الحالي على القرص.
- **واجهة رسومية** للتاجر ولفريق المراجعة. كل العمليات متاحة الآن عبر الـAPI.
