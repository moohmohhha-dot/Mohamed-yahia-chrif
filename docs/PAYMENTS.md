# نظام الدفع — Payment Service

## خدمة مستقلة

الدفع **خدمة منفصلة** (`apps/payments`) وليس جزءًا من ARUMA CORE:

| | ARUMA CORE | Payment Service |
|---|---|---|
| قاعدة البيانات | مخطط `public` | مخطط `payments` خاص بها، وجداولها الخاصة |
| الأسرار | لا يعرف أي مفتاح لمزوّد الدفع | وحدها تملك مفتاح Chargily |
| التواصل | يطلب الدفع عبر API داخلي محمي برمز (`PAYMENTS_SERVICE_TOKEN`) | ترسل الأحداث موقّعة (HMAC) إلى ARUMA CORE، مع إعادة المحاولة |

هذا هو الاستثناء الذي ذكرناه في [ARCHITECTURE.md](ARCHITECTURE.md): **المال والأسرار سبب حقيقي للعزل.**
يمكن تشغيل الخدمة على خادم منفصل، بمستخدم قاعدة بيانات منفصل، وبصلاحيات أضيق.

**لا تُخزَّن أي بيانات بطاقة في ARUMA.** الزبون يكتب رقم بطاقته في صفحة المزوّد (Chargily) وليس عندنا. نحتفظ فقط بمعرّف الدفع عند المزوّد، والمبلغ، والحالة. اختبار آلي يتأكد أن قاعدة بيانات الدفع لا تحتوي أي عمود لبيانات بطاقة.

## الحالات

| الحالة | المعنى |
|---|---|
| **Pending** | ينتظر الدفع (أو الاستلام نقدًا) |
| **Successful** | المال وصل، وتأكدنا منه عند المزوّد |
| **Failed** | فشلت المحاولة، ويمكن إعادة المحاولة |
| **Cancelled** | أُلغي قبل الدفع (إلغاء الطلب أو انتهاء المهلة) |
| **Refunded** | أُعيد المبلغ كاملًا. الاسترجاع الجزئي يبقي الحالة Successful مع «المبلغ المسترجَع» |

## ما يدعمه النظام

| المتطلب | كيف |
|---|---|
| **Online Payment** | دفعة واحدة لكل عملية شراء، حتى لو كانت عند عدة تجار. الزبون يُحوَّل إلى صفحة المزوّد. التاجر **لا يستطيع تأكيد الطلب قبل الدفع** |
| **Cash on Delivery** | دفعة لكل طلب. عند «تم التسليم» يُسجَّل المبلغ كمستلَم في خدمة الدفع، بنفس المبلغ بالضبط |
| **Refund / Partial Refund** | للمدير فقط، لكل طلب: مبلغ كامل أو جزئي، ولا يتجاوز أبدًا ما دُفع. الطلب الملغى أو المرتجع يصبح «Refunded» عند اكتمال الاسترجاع |
| **Payment Retry** | بعد الفشل: محاولة جديدة بصفحة دفع جديدة، والمحاولات السابقة محفوظة |
| **Webhooks** | تُحفظ كلها، ويُتحقق من توقيعها، والحدث الواحد يُعالَج مرة واحدة، وإذا فشلت معالجته تُعاد عند وصوله مجددًا |
| **Payment Verification** | لا نثق في الـwebhook ولا في رجوع الزبون: نعيد قراءة الدفع من المزوّد نفسه، ونقارن **المبلغ والعملة**. أي اختلاف يُفشل الدفع ويُرفع للمراجعة |
| **Idempotency** | إنشاء الدفع والاسترجاع يتطلبان `Idempotency-Key`؛ إعادة الطلب لا تدفع ولا تسترجع مرتين |

حالات خاصة مغطاة:
- **دفع وصل بعد الإلغاء** (الزبون دفع من نافذة قديمة): المال يُسجَّل ولا يضيع، ويُنبَّه المدير لإرجاعه.
- **الدفع مرتين** (محاولتان ناجحتان): يُسجَّل ويُرفع للمراجعة.
- **عملية شراء أونلاين غير مدفوعة بعد ساعة:** تُلغى تلقائيًا ويعود المخزون.
- **إلغاء طلب أونلاين غير مدفوع:** يُلغي كل طلبات نفس عملية الشراء، لأنها دفعة واحدة.

السجلات محمية في قاعدة البيانات:
- **تاريخ الحالات** لا يُعدَّل ولا يُحذف.
- **مبلغ الدفع وعملته** لا يتغيران بعد الإنشاء.
- **المبلغ المسترجَع** لا ينقص أبدًا.

## المزوّد الخارجي: Chargily Pay

**الاسم:** Chargily Pay (الإصدار V2)، من شركة Chargily الجزائرية.

**سبب الاستعمال:**
- يقبل وسيلتي الدفع الإلكتروني في الجزائر: **CIB** (البطاقة البنكية عبر SATIM) و**الذهبية / EDAHABIA** (بريد الجزائر).
- يعمل بالدينار الجزائري.
- يوفر صفحة دفع مستضافة عنده، فلا تمر بيانات البطاقة عبر ARUMA.
- له API ومكتبات رسمية منشورة.

البديل هو الربط المباشر مع **SATIM** عبر بنك جزائري، لكنه يحتاج عقدًا مع البنك ووقتًا أطول. لم أبنه، والبنية تسمح بإضافته كمزوّد آخر.

**مجاني أم مدفوع:**
- **فتح الحساب:** لا أعرف إن كان مجانيًا، تحقّق منه.
- **عمولة على كل عملية:** نعم. الـAPI فيه خيار `pass_fees_to_customer` لتحميلها على الزبون.
- **النسب الحالية:** لا أستطيع تأكيدها من هنا، **تحقّق منها في موقع Chargily قبل الإطلاق.**

**التسجيل:**
1. أنشئ حسابًا في Chargily Pay من موقعهم (chargily.com).
2. ستعمل أولًا في **وضع الاختبار (Test mode)**.
3. للانتقال إلى **الوضع الحقيقي (Live mode)** يطلب Chargily التحقق من حسابك بوثائق نشاطك. اتبع خطواتهم في لوحة التحكم.

**الحصول على مفتاح الـAPI:**
- من لوحة تحكم Chargily، في قسم المطوّرين، يوجد مفتاح سري **للاختبار** وآخر **للإنتاج**.
- ARUMA يحتاج **المفتاح السري (secret key)** فقط. يُستعمل لطلب الدفع، ولقراءته، وللتحقق من توقيع الـwebhook.

**أين توضع الأسرار:**
- **في خدمة الدفع فقط:** المتغير `CHARGILY_SECRET_KEY` في بيئة `apps/payments`.
- **لا يوضع أبدًا في:**
  - ARUMA CORE.
  - مركز التاجر أو أي واجهة.
  - الكود أو git (`.env` مستثنى من git).
- **في الإنتاج:** ضعه في مدير الأسرار الخاص بالاستضافة.
- **إذا تسرّب:** ألغِه من لوحة Chargily فورًا وأنشئ واحدًا جديدًا.
- **الأسرار الداخلية:** `PAYMENTS_SERVICE_TOKEN` و`PAYMENTS_EVENTS_SECRET` تُولَّد بـ `openssl rand -hex 32`. كل واحد منهما يوضع بنفس القيمة في الخدمتين.

**عنوان الـwebhook:**
- خدمة الدفع ترسل لـChargily مع كل عملية دفع العنوان `PAYMENTS_PUBLIC_URL/webhooks/chargily`، فلا حاجة لضبطه يدويًا.
- يجب أن يكون هذا العنوان **عامًا وبـHTTPS**.
- محليًا، يمكن استعمال أداة مثل ngrok، كما تنصح مكتبة Chargily الرسمية.

**الاختبار:**
1. ضع الإعدادات التالية في `apps/payments`:
   ```
   ONLINE_PROVIDER=chargily
   CHARGILY_MODE=test
   CHARGILY_SECRET_KEY=<المفتاح السري للاختبار>
   PAYMENTS_PUBLIC_URL=<عنوان عام HTTPS يصل إلى الخدمة>
   ```
2. فعّل الدفع الإلكتروني للمتجر بالخاصية `checkout.online_payment`.
3. ضع طلبًا بـ `paymentMethod: "online"`، وافتح `redirectUrl`، وادفع ببطاقات الاختبار المذكورة في وثائق Chargily.
4. تأكد من وصول الـwebhook (الطلب يصبح «مدفوع»).
5. **تحقّق من وحدة المبلغ:**
   - المكتبات الرسمية ترسل المبلغ بالدينار (مثال `amount: 5000`)، والخدمة مضبوطة على ذلك (`CHARGILY_AMOUNT_UNIT=major`).
   - تأكد في أول دفعة اختبار أن المبلغ الظاهر في صفحة Chargily صحيح.
   - إذا ظهر أصغر بـ100 مرة، غيّر القيمة إلى `minor`.

**ما بُني بالضبط من وثائق Chargily:**

لم أستطع فتح موقع وثائقهم من بيئة التطوير، فبنيت الربط من **الكود المصدري لمكتبتيهم الرسميتين** على GitHub ([JavaScript](https://github.com/Chargily/chargily-pay-javascript) و[Go](https://github.com/Chargily/chargily-pay-go)):
- **عناوين الـAPI:** `https://pay.chargily.net/test/api/v2` و`https://pay.chargily.net/api/v2`.
- **المصادقة:** `Authorization: Bearer <secret key>`.
- **إنشاء الدفع:** `POST checkouts`، يُرجع `checkout_url`.
- **قراءة الدفع:** `GET checkouts/{id}`، والحالات `pending / processing / paid / failed / canceled`.
- **الـwebhook:** ترويسة `signature` = HMAC-SHA256 للنص الخام بالمفتاح السري، والأحداث `checkout.paid` و`checkout.failed`.
- **الاختبارات:** تعمل على خادم محلي يحاكي هذا السلوك. اختبار حقيقي مع حساب Chargily تجريبي ضروري قبل الإطلاق.

**الاسترجاع مع Chargily:**
- مكتباتهم الرسمية لا تحتوي أي دالة للاسترجاع، **فلم أخترع واحدة.**
- يُرجَع المال خارج ARUMA (عبر Chargily أو بتحويل بنكي/بريدي)، ثم يُسجَّل في ARUMA مع **مرجع الإثبات** (`externalReference`).
- نفس الشيء للدفع عند الاستلام.

**خارج الجزائر لاحقًا:** يُضاف مزوّد آخر (مثل مزوّد دولي في دولة يدعمها) كمحوّل جديد بنفس الواجهة. لا شيء آخر يتغير.

## التطوير بدون حساب: Sandbox

- **ما هو:** `ONLINE_PROVIDER=sandbox` هو الإعداد الافتراضي محليًا. صفحة دفع وهمية على `/sandbox/checkouts/:id` فيها أزرار «دفع / فشل / إلغاء»، تمر بنفس المسار الكامل: الـwebhook الموقّع، والتحقق، والأحداث.
- **ليس مزوّد دفع حقيقيًا:** الخدمة **ترفض التشغيل به في وضع الإنتاج**.

## التشغيل

```bash
pnpm db:migrate:payments      # جداول خدمة الدفع
pnpm dev:payments             # خدمة الدفع على :3200
pnpm dev                      # ARUMA CORE على :3000
```

## الواجهات

**خدمة الدفع (داخلية، لـARUMA CORE فقط):**
- `POST /v1/payment-intents` (Idempotency-Key)
- `GET /v1/payment-intents/:id`
- `POST /v1/payment-intents/:id/retry`
- `POST /v1/payment-intents/:id/verify`
- `POST /v1/payment-intents/:id/cancel`
- `POST /v1/payment-intents/:id/cash-collected`
- `POST /v1/payment-intents/:id/refunds` (Idempotency-Key)
- عام: `POST /webhooks/:provider`

**ARUMA CORE:**

| الطريقة | المسار | من |
|---|---|---|
| POST | `/v1/stores/:slug/orders` (`paymentMethod: online \| cash_on_delivery`) | الزبون |
| GET | `/v1/me/checkouts/:id/payment?verify=true` | الزبون (عند الرجوع من صفحة الدفع) |
| POST | `/v1/me/checkouts/:id/payment/retry` | الزبون |
| POST | `/v1/admin/orders/:id/refunds` (Idempotency-Key) | المدير فقط |
| POST | `/internal/payments/events` | خدمة الدفع فقط (توقيع HMAC + طابع زمني لا يتجاوز 5 دقائق) |

## قبل الإطلاق
1. حساب Chargily ومفتاح الاختبار، ثم دفعة اختبار كاملة (والتحقق من وحدة المبلغ).
2. تفعيل الوضع الحقيقي بعد تحقق Chargily من الحساب.
3. عنوان HTTPS عام لخدمة الدفع.
4. أسرار قوية ومختلفة في مدير الأسرار.
5. تفعيل `checkout.online_payment` للمتجر.
