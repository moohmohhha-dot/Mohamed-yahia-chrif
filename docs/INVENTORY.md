# نظام المخزون — Inventory

## المفاهيم

| المصطلح | المعنى |
|---|---|
| **On hand** (في المخزن) | ما هو موجود فعليًا في المستودع |
| **Reserved** (محجوز) | ما خُصّص لطلبات لم تُشحن بعد |
| **Available** (متاح للبيع) | `On hand − Reserved`: ما يمكن لزبون جديد شراؤه |
| **SKU** | رمز التاجر للعرض، فريد لكل تاجر. يُستعمل في الاستيراد والتصدير والـAPI |
| **Variant** | الحجم أو الخيار في الكتالوج. العرض هو «هذا التاجر يبيع هذا الحجم» |
| **Location** (مستودع) | مكان تخزين. لكل تاجر مستودع افتراضي `MAIN`، ويمكنه إضافة مستودعات أخرى |
| **Low stock** | تنبيه عندما يصبح المتاح أقل من أو يساوي حدًّا يحدده التاجر لكل عرض (5 افتراضيًا) |

## دورة حياة الطلب

```
إنشاء الطلب   → reserveStock   : Reserved += الكمية      (Available ينقص، On hand لا يتغير)
إلغاء الطلب   → releaseStock   : Reserved −= الكمية      (Available يعود)
شحن الطلب     → consumeStock   : Reserved −= الكمية، On hand −= الكمية
حجز مؤقت (سلة/دفع) ينتهي وقته → releaseExpiredReservations يحرّره تلقائيًا
```

هذه الدوال موجودة في `apps/core/src/modules/inventory` وجاهزة لوحدة الطلبات القادمة. **التاجر لا يستطيع إنشاء أو إلغاء حجز بنفسه.**

## منع البيع الزائد (Overselling)

ثلاث طبقات حماية:
1. **قفل صفوف المخزون أثناء الحجز:** كل سطر يُفحص مقابل المتاح والصفوف مقفلة، والطلب كله يمر أو لا يمر شيء منه (all-or-nothing).
2. **أمان إعادة المحاولة (idempotency):**
   - إعادة نفس الطلب لا تحجز مرتين.
   - الإلغاء المزدوج لا يحرّر مرتين.
3. **قاعدة البيانات نفسها:** ترفض أي حالة يكون فيها المحجوز أكبر من الموجود (`reserved ≤ on_hand`)، حتى لو أخطأ الكود.

مُختبر: 20 طلبًا متزامنًا على 5 وحدات تُنتج 5 نجاحات بالضبط و15 رفضًا (`OUT_OF_STOCK`).

لا يمكن أيضًا إنقاص المخزون أو جرده أو تحويله تحت ما هو محجوز لطلبات.

## المستودعات والتحويل

- الحجز يأخذ من المستودع الافتراضي أولًا، ثم من المستودعات الأكثر مخزونًا. يمكن أن يتوزع سطر واحد على أكثر من مستودع.
- التحويل بين مستودعين يمس **المتاح فقط**، ويُسجَّل كحركتين مرتبطتين بنفس المرجع (`transfer_out` و`transfer_in`).
- لا يمكن أرشفة المستودع الافتراضي، ولا مستودع ما زال فيه مخزون.

## السجل (Inventory History)

- **كل تغيير يُسجَّل كحركة:** المستودع، تغيّر الموجود، تغيّر المحجوز، الكمية بعد التغيير، السبب، المرجع (طلب، تحويل، استيراد)، والفاعل.
- **السجل لا يُعدَّل ولا يُحذف**، وذلك مفروض في قاعدة البيانات.
- **مجاميع العرض** (`on_hand_quantity`, `reserved_quantity`, `available_quantity`) يحسبها **trigger** في قاعدة البيانات من مستويات المستودعات، فلا يمكن أن تختلف عنها.

## الاستيراد والتصدير (CSV / Excel)

- الأعمدة:
  - `sku` و`quantity`: إلزاميان.
  - `location`، و`mode` (`set` للجرد أو `adjust` للزيادة/النقص)، و`note`: اختيارية.
- أسماء الأعمدة مقبولة بالفرنسية والعربية أيضًا: `quantité`، `emplacement`، `الكمية`، `المستودع`.
- الفاصل `,` أو `;`، ويُكتشف تلقائيًا (Excel الفرنسي يستعمل `;`).
- **الخطوة 1 (فحص):** كل سطر يُفحص ويظهر «قبل ← بعد» أو الخطأ، **دون أي حفظ**.
- **الخطوة 2 (تطبيق):** كل الأسطر تُحفظ في معاملة واحدة. إذا كان سطر واحد خاطئًا، لا يُحفظ شيء.
- **حدود الملف:** 5000 سطر و5 ميغابايت.
- **التصدير:** بنفس صيغة الاستيراد، فيمكن التعديل في Excel ثم إعادة الاستيراد. الخلايا التي تبدأ بـ `=` تُعطَّل لمنع حقن الصيغ.

## واجهة Inventory API (v1)

كل المسارات تحت `/v1/merchants/:merchantId/inventory`، وتتطلب أن يكون المستخدم عضوًا في التاجر.

| الطريقة | المسار | الدور |
|---|---|---|
| GET | `/` (`?lowStock=true&q=&locationId=`) | كل الأعضاء |
| GET | `/locations` | كل الأعضاء |
| POST / PATCH | `/locations`, `/locations/:id` | المالك، المدير |
| POST | `/offers/:offerId/adjust` (`delta`, `reason`, `locationId?`) | كل الأعضاء |
| POST | `/offers/:offerId/count` (`quantity`, `locationId?`) | كل الأعضاء |
| PUT | `/offers/:offerId/low-stock-threshold` | كل الأعضاء |
| GET | `/offers/:offerId/history` | كل الأعضاء |
| POST | `/transfers` | المالك، المدير |
| GET | `/reservations?status=active` | كل الأعضاء (اطلاع فقط) |
| POST | `/import?dryRun=true` (ملف multipart) | المالك، المدير |
| GET | `/export?format=csv\|xlsx` | كل الأعضاء |

مفاتيح API للتطبيقات الخارجية (ربط برنامج مخزون التاجر مباشرة) تأتي مع ARUMA Developers.
